# 05 · 剪贴板模块

> 适用阶段：M4。
> 参照对象：macOS 上的 Paste（视觉与交互）、EcoPaste（技术实现）。

---

## 1. 采集

### 1.1 监听机制

Windows 上用 `AddClipboardFormatListener` 注册剪贴板变化通知，收到 `WM_CLIPBOARDUPDATE` 消息后读取内容。**不要用轮询**（`GetClipboardSequenceNumber` 定时查），那会持续占用 CPU。

`clipboard-rs` crate 已经封装好了跨平台的监听，直接用它的 `ClipboardWatcher`。

### 1.2 读取顺序

剪贴板里同一份内容通常有多种格式。按以下优先级读取，**全部保存**（不是只存一种）：

```
1. CF_HDROP          文件路径列表        → type = files
2. CF_BITMAP / PNG   图片               → type = image
3. HTML Format       HTML 片段          → 存入 content_html
4. CF_RTF            富文本             → 存入 content_rtf
5. CF_UNICODETEXT    纯文本             → 存入 content_text
```

判定主类型的规则：
- 有文件路径 → `files`
- 有图片且**没有文本** → `image`
- 有图片且有文本（比如从网页复制的图文混排）→ `text`，图片作为附件存
- 有 HTML → `text`（但 `has_html = true`，粘贴时可选带格式）
- 只有纯文本 → `text`
- 纯文本内容符合 URL 正则 → `link`（单独一个类型，卡片上显示网页图标和域名）
- 纯文本符合颜色格式（`#RRGGBB` / `rgb(...)`）→ `color`（卡片上显示色块）

### 1.3 去重

计算内容哈希：

```
text/link/color:  sha256(content_text)
html:             sha256(content_text)   // 用纯文本部分算，避免同样的文字因 HTML 属性微小差异被当成两条
image:            sha256(原始图片字节)
files:            sha256(路径列表按序拼接)
```

新内容的哈希若与**最近 200 条**中的某条相同：
- 不新增记录
- 把那条已有记录的 `last_used_at` 更新为当前时间，让它冒到列表最前面
- 不改变它的 `created_at`

### 1.4 大小限制

| 类型 | 上限 | 超限处理 |
|---|---|---|
| 文本 | 5 MB | 截断保存，标记 `truncated = true`，卡片上提示"内容过长，已截断" |
| 图片 | 30 MB | 不保存，记一条日志 |
| 文件列表 | 500 条 | 只存前 500 条 |

上限值在设置里可调。

### 1.5 图片的存储

图片**不存进数据库**（BLOB 会让数据库膨胀、查询变慢）。存文件：

```
%APPDATA%/CHENOCR/clipboard/
├── 2026/08/
│   ├── {uuid}.png          原图
│   └── {uuid}.thumb.webp   缩略图，最长边 320px，质量 80
```

数据库里只存相对路径。启动时做一次孤儿文件清理（文件在但数据库里没记录的，删掉）。

### 1.6 来源应用

用 `GetForegroundWindow` + `GetWindowThreadProcessId` + `QueryFullProcessImageName` 拿到当前前台进程的可执行文件路径，再用 `SHGetFileInfo` 提取它的图标。

- 应用名和路径存 `source_app` / `source_app_path`
- 图标提取一次后缓存到 `%APPDATA%/CHENOCR/app-icons/{exe名的hash}.png`，不要每条记录都提取
- 提取失败时用一个通用的占位图标，不要报错

⚠ 剪贴板变化通知到达时，前台窗口可能已经切换。缓解：在收到通知后**立即**（同步地）取前台窗口，不要等异步任务。

### 1.7 忽略规则

三种情况不记录：

1. **黑名单应用**（设置里配置，**默认为空**）—— 前台进程在黑名单里，跳过
2. **敏感标记** —— 剪贴板里带有 `ExcludeClipboardContentFromMonitorProcessing` 或 `CanIncludeInClipboardHistory=0` 这两个剪贴板格式（密码管理器会设置它们）。**默认也记录**，但设置里有一个"尊重应用的隐私标记"开关
3. **程序内部标记** —— CHENOCR 自己写剪贴板时（比如划词翻译的模拟复制、用户点击"粘贴"回填），设置 `ignore_next_change` 标志，跳过一次

按用户决策：**1 和 2 默认关闭，即默认全量记录。**

## 2. 数据库

见 `07-跨平台抽象层与数据存储.md` 的完整 schema。这里只列剪贴板相关：

```sql
CREATE TABLE clipboard_items (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  type          TEXT NOT NULL,          -- text|link|color|image|files|html
  content_text  TEXT,                   -- 纯文本内容（所有类型都尽量填，用于搜索）
  content_html  TEXT,
  content_rtf   TEXT,
  file_path     TEXT,                   -- 图片相对路径
  thumb_path    TEXT,
  file_list     TEXT,                   -- JSON 数组，files 类型用
  preview       TEXT,                   -- 列表展示用的短预览，最多 200 字
  hash          TEXT NOT NULL,
  char_count    INTEGER,
  size_bytes    INTEGER,
  width         INTEGER,                -- 图片宽
  height        INTEGER,
  source_app    TEXT,
  source_app_path TEXT,
  truncated     INTEGER NOT NULL DEFAULT 0,
  pinned        INTEGER NOT NULL DEFAULT 0,
  favorite      INTEGER NOT NULL DEFAULT 0,
  note          TEXT,
  group_id      INTEGER REFERENCES clipboard_groups(id) ON DELETE SET NULL,
  created_at    INTEGER NOT NULL,
  last_used_at  INTEGER NOT NULL,
  -- 第二阶段同步预留，第一版必须建但不使用
  sync_id       TEXT,
  sync_rev      INTEGER NOT NULL DEFAULT 0,
  sync_state    INTEGER NOT NULL DEFAULT 0,   -- 0=本地 1=待上传 2=已同步
  device_id     TEXT
);

CREATE INDEX idx_clip_last_used ON clipboard_items(last_used_at DESC);
CREATE INDEX idx_clip_hash      ON clipboard_items(hash);
CREATE INDEX idx_clip_type      ON clipboard_items(type, last_used_at DESC);
CREATE INDEX idx_clip_pinned    ON clipboard_items(pinned, last_used_at DESC) WHERE pinned = 1;
CREATE INDEX idx_clip_sync      ON clipboard_items(sync_state) WHERE sync_state = 1;

CREATE TABLE clipboard_groups (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL,
  color      TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);

CREATE VIRTUAL TABLE clipboard_fts USING fts5(
  content_text,
  note,
  source_app,
  content = 'clipboard_items',
  content_rowid = 'id',
  tokenize = 'unicode61 remove_diacritics 2'
);
```

### 2.1 中文分词问题

FTS5 默认的 `unicode61` 分词器**不切分中文**，整段中文会被当成一个词，导致搜"文档"搜不到"这是一份文档"。

解决方案（按推荐度）：

1. **在写入 FTS 时对中文做 bigram 切分**（推荐，零依赖）
   把 `你好世界` 转成 `你好 好世 世界` 存进 FTS 的索引列。搜索时对查询词做同样处理。
   实现：写一个 `to_search_tokens(text: &str) -> String`，CJK 字符两两成对，非 CJK 按空格切。
   代价：索引体积约为原文的 2 倍，可接受。

2. 启用 SQLite 的 `trigram` 分词器（`tokenize = 'trigram'`）—— 支持子串搜索，但索引更大且不支持前缀查询

3. 引入 jieba-rs 做真分词 —— 效果最好，但增加约 5 MB 词典体积

**第一版用方案 1。**

### 2.2 触发器

FTS 表要和主表同步：

```sql
CREATE TRIGGER clip_ai AFTER INSERT ON clipboard_items BEGIN
  INSERT INTO clipboard_fts(rowid, content_text, note, source_app)
  VALUES (new.id, new.search_tokens, new.note, new.source_app);
END;
-- 同理 clip_ad (DELETE) / clip_au (UPDATE)
```

注意：`search_tokens` 是分词后的结果，需要在主表加一列存它，或者在 Rust 侧插入时同时写两张表（推荐后者，避免主表膨胀，但要保证在同一事务里）。

### 2.3 保留策略

**默认不自动清理**（用户要求全量保留）。

设置里提供可选的清理策略，默认关闭：
- 保留最近 N 天（30/90/180/365）
- 保留最多 N 条（10000/50000/无限）
- 清理时**永不删除**已置顶、已收藏、有备注、已分组的条目

手动清理入口：设置页的「清空剪贴板历史」按钮，二次确认。

## 3. 面板界面

### 3.1 两种形态

**默认：底部横向卡片条**（Paste 风格）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  🔍 搜索…              全部  文字  图片  链接  文件    置顶  收藏      ⚙  ✕  │
├─────────────────────────────────────────────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐  │
│  │📌       │ │         │ │         │ │  [图片] │ │         │ │         │  │
│  │这是一段  │ │https:// │ │  #FF5733│ │  预览   │ │一段很长  │ │文件.zip │  │
│  │文本内容  │ │example  │ │         │ │         │ │的文本... │ │         │  │
│  │         │ │.com     │ │         │ │         │ │         │ │         │  │
│  ├─────────┤ ├─────────┤ ├─────────┤ ├─────────┤ ├─────────┤ ├─────────┤  │
│  │💬 微信   │ │🌐 Chrome│ │🎨 Figma │ │📷 截图  │ │📝 记事本│ │📁 资源  │  │
│  │2分钟前   │ │5分钟前  │ │昨天     │ │昨天     │ │3天前    │ │上周     │  │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 窗口：全屏宽，高 320px，吸附在屏幕底部（任务栏之上）
- 卡片：宽 168px，高 216px，间距 12px，圆角 12px
- 出现动画：从下方 320px 滑入，280ms，缓动 `cubic-bezier(0.32, 0.72, 0, 1)`（iOS sheet 曲线）
- 消失动画：滑出，200ms（退出比进入快，这是苹果的规律）

**可选：竖版小面板**（Win+V 风格，设置里切换）

- 窗口 380×620，出现在鼠标位置附近（自动避开屏幕边缘）
- 卡片横向铺满，高度 72px（文本）/ 120px（图片）
- 从鼠标位置 `scale(0.96) + opacity 0` 展开，180ms

### 3.2 卡片内容

| 类型 | 卡片上显示什么 |
|---|---|
| text | 前 6 行文字（超出渐隐），右上角小字显示字数 |
| link | 网站 favicon + 标题（若能取到）+ 域名。取不到就显示 URL |
| color | 整张卡片是那个颜色，中间白/黑字显示色值（根据亮度自动选文字颜色） |
| image | 缩略图 `object-fit: cover`，右上角小字显示 `1920×1080` |
| files | 文件类型图标 + 文件名。多个文件显示"文件名 等 N 个文件" |

卡片底部固定一条 28px 的信息栏：来源应用图标（16×16）+ 应用名 + 相对时间。

置顶的卡片左上角有一个 📌 角标，且**永远排在最前面**。

### 3.3 交互

| 操作 | 行为 |
|---|---|
| `Alt+V` | 打开/关闭面板 |
| 直接打字 | 自动聚焦搜索框并输入 |
| `←` `→`（横向）/ `↑` `↓`（竖版） | 移动选中 |
| `Enter` | 粘贴选中项到之前的活动窗口并关闭面板 |
| `Ctrl+Enter` | 粘贴为纯文本 |
| `Shift+Enter` | 只复制到剪贴板，不粘贴，不关闭面板 |
| `1`–`9`（搜索框未聚焦时） | 直接粘贴第 N 项 |
| `Space` | 快速预览（大图/全文，类似 macOS 的空格预览） |
| `Delete` | 删除选中项 |
| `Ctrl+P` | 置顶/取消置顶 |
| `Ctrl+D` | 收藏/取消收藏 |
| 单击卡片 | 选中 |
| 双击卡片 | 粘贴并关闭 |
| 右键卡片 | 上下文菜单 |
| 拖拽卡片到其他应用 | 直接拖出内容（文本/图片/文件） |
| `Esc` | 关闭面板 |
| 点击面板外部 | 关闭面板 |
| `Tab` | 在类型筛选标签之间切换 |

**右键菜单**：粘贴 · 粘贴为纯文本 · 复制 · ─ · 置顶 · 收藏 · 添加备注 · 移到分组▸ · ─ · 翻译 · 识别文字（图片） · 在文件夹中显示（文件） · 用浏览器打开（链接） · ─ · 删除

### 3.4 粘贴的实现

这是个技术难点。流程：

1. 记录当前的前台窗口句柄（**在面板打开之前**就要记，因为面板打开后前台窗口变成了面板自己）
2. 用户选中某项按 Enter
3. 把内容写入系统剪贴板
4. 隐藏面板
5. 用 `SetForegroundWindow` 把焦点还给记录的那个窗口
6. 等待 ~50ms 让焦点切换完成
7. 用 `SendInput` 模拟 `Ctrl+V`

⚠ 坑点：

- `SetForegroundWindow` 在 Windows 上有限制，非前台进程调用它可能失败。解决办法是先调 `AllowSetForegroundWindow` 或用 `AttachThreadInput` 附加到目标线程的输入队列
- 模拟 Ctrl+V 时，如果用户还按着 Alt（Alt+V 的 Alt 还没松），会变成 Ctrl+Alt+V。必须先发送所有修饰键的 keyup
- 剪贴板面板窗口要设置 `focus: false` 打开吗？不行，搜索框需要焦点。所以必须走上面这套焦点还原流程
- 这次自己写剪贴板的动作要设 `ignore_next_change`，否则会在历史里多出一条重复记录（除非用户就是想让它冒泡到最前，那就更新 `last_used_at` 而不是新增）

**决定**：粘贴动作会更新该条的 `last_used_at`，让它冒到最前，但不新增记录。

### 3.5 性能

- 列表必须用 `@tanstack/react-virtual` 虚拟滚动，只渲染可见的卡片 + 前后各 3 个
- 图片缩略图用 `loading="lazy"`
- 搜索输入防抖 200ms
- 分页：一次拉 50 条，滚到底部继续拉。用 keyset 分页（`WHERE last_used_at < ?`），不要用 `OFFSET`
- 面板窗口**常驻但隐藏**，不要每次打开都创建。打开只是 `show()` + 刷新数据，这样能做到瞬间响应

## 4. 主窗口的剪贴板页

面板是快速取用，主窗口的页面是**管理**。

```
┌──────────┬────────────────────────────────────────────────────────┐
│ 截图库    │  剪贴板                              🔍 搜索…    ⋯     │
│ ● 剪贴板  │  ┌──────────────────────────────────────────────────┐ │
│ 识字记录  │  │ 全部 12,483 · 置顶 8 · 收藏 42                    │ │
│ 设置      │  ├──────────────────────────────────────────────────┤ │
│           │  │ □ 这是一段文本内容                    微信  2分钟 │ │
│ ── 分组 ──│  │ □ https://example.com                Chrome 5分钟│ │
│ 工作      │  │ □ [图片] 1920×1080                    截图  昨天 │ │
│ 代码片段  │  │ ...                                              │ │
│ 常用回复  │  └──────────────────────────────────────────────────┘ │
└──────────┴────────────────────────────────────────────────────────┘
```

- 列表视图（不是卡片），信息密度高
- 支持多选（Shift 连选、Ctrl 点选）批量操作：删除、移到分组、导出
- 左侧显示分组，可拖拽条目到分组上
- 顶部 ⋯ 菜单：导出全部 / 导入 / 清理设置 / 打开数据文件夹
- 点击某条，右侧展开详情面板：完整内容、元信息（大小、字数、时间、来源）、备注编辑

## 5. 导入导出

- 导出格式：`.chenocr-clip` —— 实际是一个 zip，里面 `data.json` + `assets/` 目录（图片文件）
- 可选加密：用户设密码，用 AES-256-GCM 加密 `data.json`，密钥用 Argon2id 从密码派生
- 导入时按 `hash` 去重，已存在的跳过
