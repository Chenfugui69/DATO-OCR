# 第一部分 · 跨平台抽象层

## 1. 原则

**只有五类东西是平台相关的，其余全部共享。**

```
src-tauri/src/platform/
├── mod.rs              trait 定义 + 平台选择
├── types.rs            共享的数据类型（Rect / MonitorInfo / WindowInfo ...）
├── windows/
│   ├── mod.rs
│   ├── capture.rs
│   ├── window_enum.rs
│   ├── clipboard.rs
│   ├── paste.rs
│   ├── vibrancy.rs
│   ├── secret.rs
│   ├── scroll_hook.rs
│   └── system_info.rs
└── macos/
    ├── mod.rs          第一版：全部 unimplemented!()，但签名必须完整
    └── ...
```

**铁律：**

1. `platform/` 之外的任何 Rust 代码，**禁止出现 `#[cfg(windows)]`**。所有平台分支都收敛在这一层
2. `platform/` 之外，**禁止 `use windows::...`**
3. 前端代码里**禁止**出现平台判断（除了标题栏按钮那一处，见 `06-UI设计规范.md` 4.6）
4. trait 的方法签名必须是平台中立的 —— 不要出现 `HWND`、`HMONITOR` 这类 Windows 类型。用 `u64` 包装的不透明句柄

## 2. Trait 定义

```rust
// src-tauri/src/platform/mod.rs

#[cfg(windows)]
pub use windows_impl as sys;
#[cfg(target_os = "macos")]
pub use macos_impl as sys;

pub trait ScreenCapture: Send + Sync {
    /// 列出所有显示器
    fn list_monitors(&self) -> Result<Vec<MonitorInfo>>;
    /// 抓取指定显示器的完整画面（物理像素）
    fn capture_monitor(&self, monitor_id: MonitorId) -> Result<RgbaImage>;
    /// 抓取所有显示器（可并行）
    fn capture_all(&self) -> Result<Vec<(MonitorId, RgbaImage)>>;
    /// 抓取虚拟桌面上的一块矩形区域
    fn capture_region(&self, rect: PhysicalRect) -> Result<RgbaImage>;
    /// 抓取指定窗口（可能失败，比如被遮挡的窗口在某些系统上抓不到）
    fn capture_window(&self, window: WindowHandle) -> Result<RgbaImage>;
}

pub trait WindowEnumerator: Send + Sync {
    /// 按 Z 序从上到下枚举所有可见的顶层窗口
    fn enumerate_top_level(&self) -> Result<Vec<WindowInfo>>;
    /// 枚举指定窗口的子控件矩形（用于截图时的区域细分检测）
    fn enumerate_children(&self, window: WindowHandle) -> Result<Vec<PhysicalRect>>;
    /// 当前前台窗口
    fn foreground_window(&self) -> Result<Option<WindowInfo>>;
    /// 把焦点还给指定窗口
    fn focus_window(&self, window: WindowHandle) -> Result<()>;
}

pub trait ClipboardMonitor: Send + Sync {
    /// 开始监听，变化时通过 channel 推送
    fn start(&self, tx: Sender<ClipboardSnapshot>) -> Result<()>;
    fn stop(&self) -> Result<()>;
    /// 读取当前剪贴板的全部格式
    fn read_all(&self) -> Result<ClipboardSnapshot>;
    /// 写入剪贴板
    fn write(&self, payload: &ClipboardPayload) -> Result<()>;
    /// 设置「忽略下一次变化」标志
    fn ignore_next(&self);
}

pub trait InputSimulator: Send + Sync {
    /// 释放所有当前按下的修饰键
    fn release_modifiers(&self) -> Result<()>;
    /// 模拟粘贴（Ctrl+V / Cmd+V）
    fn send_paste(&self) -> Result<()>;
    /// 模拟复制（Cmd+C），用于划词翻译
    fn send_copy(&self) -> Result<()>;
}

pub trait WindowEffects: Send + Sync {
    fn probe_capabilities(&self) -> VisualCapabilities;
    fn apply_backdrop(&self, window: &WebviewWindow, kind: BackdropKind) -> Result<()>;
    fn set_click_through(&self, window: &WebviewWindow, enabled: bool) -> Result<()>;
    fn exclude_from_capture(&self, window: &WebviewWindow) -> Result<()>;
}

pub trait SecretStore: Send + Sync {
    fn protect(&self, plain: &[u8]) -> Result<Vec<u8>>;
    fn unprotect(&self, cipher: &[u8]) -> Result<Vec<u8>>;
}

pub trait ScrollListener: Send + Sync {
    /// 非拦截式监听全局滚轮事件，用于长截图
    fn start(&self, tx: Sender<ScrollEvent>) -> Result<()>;
    fn stop(&self) -> Result<()>;
}

pub trait SystemInfo: Send + Sync {
    fn is_dark_mode(&self) -> bool;
    fn is_transparency_enabled(&self) -> bool;
    fn is_power_saver(&self) -> bool;
    fn is_reduced_motion(&self) -> bool;
    /// CPU 是否支持 AVX（决定 PaddleOCR 能否使用）
    fn supports_avx(&self) -> bool;
    fn device_id(&self) -> String;
}
```

### 2.1 M0 已落地的补充契约

M0 的截图链路对上面的初始草案做了几处必要的补充。下面这些接口已经属于跨平台契约，
后续实现不得只按旧草案理解：

#### `ScreenCapture::warm_up` 与失效重热

`ScreenCapture` 还提供一个不返回图像的启动热身：

```rust
pub trait ScreenCapture: Send + Sync {
    // ...上面的抓屏方法...
    /// 预先支付首次抓屏的设备/会话初始化开销，结果丢弃。
    fn warm_up(&self);
}
```

Windows 上这一步会在后台线程空跑一次抓屏，提前建立 D3D/WGC 状态；失败只记日志，
不影响功能。GPU 侧热身状态并不永久有效，因此平台层还提供状态失效通知：

```rust
pub fn on_capture_state_lost(handler: fn());
```

`capture::warmup::install()` 在启动时调度一次热身并订阅该通知。显示器插拔、分辨率或
缩放变化、睡眠唤醒等事件触发后，平台实现通过真正的顶层监听窗口收到广播，再请求一次
热身。通知回调必须立刻返回，实际抓屏放到后台线程；多个连续事件用原子
`compare_exchange` 去抖，避免重复支付初始化开销。热身失败仍只记录日志，下一次真实抓屏
负责恢复状态。

#### `WindowEffects::native_handle`

为让原生底图层把遮罩放到正确的 z 序，`WindowEffects` 增加：

```rust
fn native_handle(&self, window: &WebviewWindow) -> Result<u64>;
```

返回值是不透明的原生窗口句柄（Windows 上是 `HWND` 的 `u64` 包装）。它只在
`platform/` 内部传给 `BackdropLayer::show_above`，平台无关代码的签名中不得泄露
`HWND` 等类型。

#### `BackdropLayer`（第八个 trait）

冻结底图不再作为 WebView 图片渲染，而是独立的原生显示层。因此除了本节原先列出的
七个 trait，平台抽象还必须实现第八个 trait：

```rust
pub trait BackdropLayer: Send + Sync {
    /// 为显示器准备（或复用）隐藏的底图窗口。
    fn ensure(&self, monitor: MonitorId) -> Result<()>;
    /// 将图像装载到窗口并定位，但保持隐藏。
    fn load(&self, monitor: MonitorId, image: &RgbaImage, at: PhysicalRect) -> Result<()>;
    /// 把底图放到遮罩正下方，与遮罩同一批次显示。
    fn show_above(&self, monitor: MonitorId, overlay: u64) -> Result<()>;
    /// 隐藏全部底图窗口但保留缓冲以便复用。
    fn hide_all(&self);
    /// 删除不再存在的显示器对应的窗口。
    fn retain(&self, keep: &[MonitorId]);
}
```

实现必须保持窗口操作的线程归属：Windows 的窗口、`HDC` 和位图只在创建它们的 UI
线程使用。`load` 与 `show_above` 分开，允许先在隐藏窗口中准备好像素，再用
`DeferWindowPos` 与透明遮罩原子上屏，避免先露出未压暗的桌面帧。底图仍通过 `shot:`
协议把原始像素异步送进 WebView，供放大镜、取色和马赛克使用，但不再阻塞遮罩显示。

## 3. 共享类型

```rust
// src-tauri/src/platform/types.rs

/// 不透明的窗口句柄。Windows 上是 HWND，macOS 上是 CGWindowID
#[derive(Copy, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct WindowHandle(pub u64);

#[derive(Copy, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct MonitorId(pub u64);

/// 物理像素坐标，原点是虚拟桌面左上角。可能为负（副屏在主屏左侧/上方时）
#[derive(Copy, Clone, Debug, Serialize, Deserialize)]
pub struct PhysicalRect { pub x: i32, pub y: i32, pub width: u32, pub height: u32 }

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MonitorInfo {
    pub id: MonitorId,
    pub name: String,
    pub bounds: PhysicalRect,
    pub work_area: PhysicalRect,     // 排除任务栏
    pub scale_factor: f64,
    pub is_primary: bool,
    pub refresh_rate: Option<u32>,
}

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct WindowInfo {
    pub handle: WindowHandle,
    /// 必须用 DWMWA_EXTENDED_FRAME_BOUNDS，不是 GetWindowRect
    pub bounds: PhysicalRect,
    pub z_order: u32,                // 0 = 最上层
    pub title: String,
    pub app_name: String,
    pub app_path: Option<PathBuf>,
    pub process_id: u32,
    pub is_minimized: bool,
    pub monitor_id: MonitorId,
}

#[derive(Clone, Debug)]
pub struct ClipboardSnapshot {
    pub text: Option<String>,
    pub html: Option<String>,
    pub rtf: Option<String>,
    pub image: Option<RgbaImage>,
    pub files: Vec<PathBuf>,
    /// 应用是否标记了「不要记录到剪贴板历史」
    pub privacy_flagged: bool,
    pub source: Option<WindowInfo>,
    pub captured_at: i64,
}

#[derive(Clone, Copy, Debug, Serialize, Deserialize)]
pub enum BackdropKind { Mica, Acrylic, Vibrancy, None }

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct VisualCapabilities {

    pub transparency_enabled: bool,
    pub reduced_motion: bool,
    pub power_saver: bool,
    pub dark_mode: bool,
}
```

## 4. Windows 实现要点

### 4.1 DPI

在 `main.rs` 最早的位置（`tauri::Builder` 之前）声明：

```rust
#[cfg(windows)]
unsafe {
    SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2);
}
```

没有这一句，混合 DPI 环境下所有坐标都是错的。

### 4.2 窗口矩形

```rust
// ✗ 错误：会多出约 7px 的不可见阴影边框
GetWindowRect(hwnd, &mut rect);

// ✓ 正确
DwmGetWindowAttribute(
    hwnd,
    DWMWA_EXTENDED_FRAME_BOUNDS,
    &mut rect as *mut _ as *mut c_void,
    size_of::<RECT>() as u32,
);
```

若 `DwmGetWindowAttribute` 失败（比如窗口已销毁），回退到 `GetWindowRect`。

### 4.3 窗口过滤

枚举时跳过：

```rust
!IsWindowVisible(hwnd)                              // 不可见
IsIconic(hwnd)                                      // 最小化
GetWindowLongW(hwnd, GWL_EXSTYLE) & WS_EX_TOOLWINDOW  // 工具窗口
rect.width == 0 || rect.height == 0                 // 零尺寸
是 DATO OCR 自己的窗口                                 // 比对 process_id
DwmGetWindowAttribute(DWMWA_CLOAKED) != 0           // UWP 的隐藏窗口（重要，
                                                    // 否则会框到不存在的 UWP 窗口）
```

### 4.4 截图窗口不被自己拍到

Windows 10 2004+ 支持 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`，被标记的窗口不会出现在抓屏结果里。

给所有 DATO OCR 的浮动窗口（截图遮罩、剪贴板面板、toast、贴图窗口）都设上。这样：
- 长截图采集时不会拍到自己的提示条
- 用户用别的截图软件截图时也不会拍到 DATO OCR 的浮层（这一点见仁见智，做成设置项）

⚠ 但**贴图窗口默认不应该排除**，用户可能就是想把贴图截进去。做成贴图窗口的右键菜单项。

### 4.5 焦点还原与模拟粘贴

```rust
pub fn paste_to_window(target: WindowHandle) -> Result<()> {
    let hwnd = HWND(target.0 as _);

    // 1. 附加到目标窗口的输入线程，绕过 SetForegroundWindow 的限制
    let target_thread = GetWindowThreadProcessId(hwnd, None);
    let current_thread = GetCurrentThreadId();
    AttachThreadInput(current_thread, target_thread, true);

    SetForegroundWindow(hwnd);
    SetFocus(hwnd);

    AttachThreadInput(current_thread, target_thread, false);

    // 2. 释放所有修饰键（用户可能还按着 Alt）
    release_modifiers()?;

    // 3. 等焦点切换稳定
    std::thread::sleep(Duration::from_millis(50));

    // 4. 发送 Ctrl+V
    send_input_ctrl_v()?;
    Ok(())
}
```

`release_modifiers` 要对 `VK_MENU`、`VK_CONTROL`、`VK_SHIFT`、`VK_LWIN`、`VK_RWIN` 逐个发 keyup。

### 4.6 低级钩子

长截图的滚轮监听用 `SetWindowsHookEx(WH_MOUSE_LL, ...)`。

⚠ 三条硬性要求：

1. 钩子必须在**有消息循环的线程**上安装。Tauri 的主线程有消息循环，但不要在主线程上装（会阻塞 UI）。开一个专用线程，自己跑 `GetMessage` 循环
2. 回调函数必须**在 300ms 内返回**（`LowLevelHooksTimeout` 默认值），超时系统会静默摘掉钩子。回调里只做 `tx.try_send(evt)`，其他什么都不做
3. 长截图会话结束后**必须 `UnhookWindowsHookEx`**。全局钩子不卸载会影响整个系统的输入性能

### 4.7 DPAPI 密钥保护

```rust
use windows::Win32::Security::Cryptography::{CryptProtectData, CryptUnprotectData, CRYPT_INTEGER_BLOB};

// 第三个参数传一个固定的 entropy（应用专属的盐），防止其他应用解开
const ENTROPY: &[u8] = b"CHENOCR.v1.secret";
```

## 5. macOS 桩

第一版 `platform/macos/` 里所有方法：

```rust
fn capture_monitor(&self, _id: MonitorId) -> Result<RgbaImage> {
    unimplemented!("macOS: 移植时用 CGWindowListCreateImage 或 ScreenCaptureKit 实现")
}
```

**每个 `unimplemented!` 都要写清楚"移植时用什么 API 实现"。** 这是给未来的自己/其他 AI 留的地图。

移植时的对应关系速查：

| trait | Windows | macOS |
|---|---|---|
| ScreenCapture | DXGI Desktop Duplication (xcap) | ScreenCaptureKit（12.3+）/ CGWindowListCreateImage。**需要「屏幕录制」权限** |
| WindowEnumerator | EnumWindows + DWM | CGWindowListCopyWindowInfo。子控件枚举需要 Accessibility API + **「辅助功能」权限** |
| ClipboardMonitor | AddClipboardFormatListener | NSPasteboard 的 `changeCount` **轮询**（macOS 没有通知机制，只能 200ms 轮询） |
| InputSimulator | SendInput | CGEventCreateKeyboardEvent。**需要「辅助功能」权限** |
| WindowEffects | Mica / Acrylic | NSVisualEffectView（`apply_vibrancy`） |
| SecretStore | DPAPI | Keychain Services |
| ScrollListener | WH_MOUSE_LL | CGEventTap。**需要「辅助功能」权限** |

⚠ **macOS 的权限申请是移植时最大的工作量**，不是 API 本身。要提前设计好首次运行的权限引导流程。

## 7. 数据库

SQLite，WAL 模式。连接池 r2d2，池大小 4。

### 7.1 初始化 PRAGMA

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;      -- WAL 下足够安全，比 FULL 快很多
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA cache_size = -20000;       -- 20 MB
PRAGMA temp_store = MEMORY;
```

```sql
-- ══════════════════════════════════════════════════════════
-- 密钥（DPAPI 加密后的二进制）
-- ══════════════════════════════════════════════════════════
CREATE TABLE secrets (
  key        TEXT PRIMARY KEY,      -- 如 'deepl_api_key' / 'openai_api_key'
  cipher     BLOB NOT NULL,
  updated_at INTEGER NOT NULL
);

-- ══════════════════════════════════════════════════════════
-- 应用黑名单
-- ══════════════════════════════════════════════════════════
CREATE TABLE app_blacklist (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  app_path   TEXT NOT NULL UNIQUE,
  app_name   TEXT,
  created_at INTEGER NOT NULL
);
```

### 7.3 迁移机制

从第一天就要有，不要等到需要改表时才加。

```rust
// src-tauri/src/storage/migrations.rs
const MIGRATIONS: &[(i32, &str)] = &[
    (1, include_str!("../../migrations/001_init.sql")),
    // (2, include_str!("../../migrations/002_xxx.sql")),
];

pub fn migrate(conn: &Connection) -> Result<()> {
    let current: i32 = conn.query_row(
        "SELECT COALESCE(MAX(version), 0) FROM schema_version", [], |r| r.get(0)
    ).unwrap_or(0);

    for (v, sql) in MIGRATIONS.iter().filter(|(v, _)| *v > current) {
        let tx = conn.unchecked_transaction()?;
        tx.execute_batch(sql)?;
        tx.execute("INSERT INTO schema_version VALUES (?, ?)", params![v, now()])?;
        tx.commit()?;
        tracing::info!("applied migration {}", v);
    }
    Ok(())
}
```

**迁移前自动备份**：升级到新的 schema 版本前，把 `chenocr.db` 复制一份到 `chenocr.db.bak.v{old}`，只保留最近一份。

### 7.4 维护任务

启动时（异步，不阻塞 UI）执行：

1. `PRAGMA integrity_check` —— 失败则提示用户，并尝试从最近的备份恢复
2. **孤儿文件清理** —— 遍历 `clipboard/` 和 `screenshots/`，删除数据库里没有记录的文件
3. **失效记录清理** —— 删除 `file_path` 指向的文件已不存在的记录
4. **清空 `temp/`**
5. 每 30 天执行一次 `VACUUM`（记录上次执行时间在 settings 里）

## 9. 数据安全

| 项 | 做法 |
|---|---|
| API 密钥 | DPAPI 加密存数据库，界面上脱敏显示 |
| 剪贴板内容 | 明文存储（用户选择）。数据目录不做加密。**在关于页明确告知用户数据存储位置和状态** |
| 日志 | 禁止记录剪贴板内容、OCR 结果、密钥。只记录长度和类型 |
| 崩溃报告 | 第一版不做上报 |
| 网络请求 | 只有翻译和检查更新会联网。设置里提供「完全离线模式」总开关，打开后禁用所有网络功能 |
| 数据导出 | 导出包可选密码加密（AES-256-GCM + Argon2id） |
