# 03 · 长截图与拼接算法

> 适用阶段：M5。
> **只做手动滚动模式，不做自动滚动。** 这是已拍板的决策。

---

## 1. 用户流程

```
按 F2（或截图编辑态点长截图按钮）
   │
   ├─ 若从 F2 进入：先走一遍正常的框选流程，确定采集区域
   ├─ 若从编辑态进入：直接沿用当前选区
   │
   ↓
进入「滚动采集态」
   │  · 选区外遮罩加深到 0.6，选区边框变成主色虚线并有缓慢流动动画
   │  · 选区正下方出现操作提示条
   │  · 屏幕右侧出现拼接预览条
   │  · 立即采集第 1 帧
   │
   ├─(用户滚动鼠标滚轮)─→ 延迟 160ms 后采集下一帧 → 尝试拼接
   │       │
   │       ├─ 拼接成功 → 预览条追加，高度数字更新
   │       └─ 拼接失败 → 提示条变黄警告，该帧暂存但不并入
   │
   ├─(Backspace)─→ 撤销最后一帧
   ├─(Esc)───────→ 放弃整个会话
   │
   ↓
按 Enter 完成
   │
   ↓
生成长图 → 进入标注编辑态（复用 02 的标注工具）→ 复制/保存
```

|---|---|---|

### 2.2 拼接预览条

位置：屏幕右侧边缘内 16px，垂直居中。宽 120px，最高 60vh。玻璃材质，圆角 12px。

- 显示到目前为止拼好的长图缩略图，等比缩放到宽 120px
- 超过容器高度时自动滚到底部，始终显示最新部分
- 每次新帧并入，新增部分有 200ms 的淡入 + 从下方 8px 上移的动画
- 底部一行小字显示 `7 帧 · 1080 × 3840`
- 有一条主色的细线标示最近一次拼接的接缝位置，方便用户发现拼歪

### 2.3 帧列表（拼接失败时展开）

拼接失败超过 2 次，预览条下方展开一个帧缩略图列表，用户可以：
- 点某一帧删除它
- 拖动重排（极少用，但拼歪时能救）

## 3. 采集时机

### 3.1 触发

监听全局鼠标滚轮事件。在 Windows 上，采集窗口是置顶透明窗口，滚轮事件**必须穿透**到底下的应用（否则用户滚不动页面）。

实现：采集窗口设置 `WS_EX_TRANSPARENT | WS_EX_LAYERED` 让鼠标事件穿透，同时用 **低级鼠标钩子**（`SetWindowsHookEx(WH_MOUSE_LL)`）在 Rust 侧监听滚轮，不拦截。

```rust
// src-tauri/src/platform/windows/scroll_hook.rs
// WH_MOUSE_LL 钩子，只监听 WM_MOUSEWHEEL，永远返回 CallNextHookEx 放行
```

⚠ 低级钩子的回调必须**极快返回**（Windows 有 LowLevelHooksTimeout 限制，默认 300ms，超时会被系统摘掉钩子）。回调里只做一件事：往 channel 发一个消息。所有实际工作在另一个线程做。

### 3.2 防抖

滚轮事件密集触发。规则：

- 收到滚轮事件后，重置一个 **160ms** 的定时器
- 定时器到期（即用户停止滚动 160ms）才采集一帧
- 160ms 是为了等待目标应用完成滚动动画和重绘。可在设置里调（100–400ms）

### 3.3 采集

调用 `xcap` 抓取**选区所在显示器**的画面，裁出选区区域。不要抓全部显示器。

⚠ 采集窗口自身是透明的，但它上面的提示条和预览条**不透明**。若它们与选区重叠会被拍进去。解决：采集前 100ms 把提示条和预览条设为 `visibility: hidden`，采集完再恢复。或者更简单——**保证它们的位置永远不与选区重叠**（提示条在选区外下方，预览条贴屏幕右边缘；若选区本身覆盖了这些位置，把它们移到选区外的其他空白处）。

## 4. 拼接算法

这是本模块的核心。放在 Rust 侧（`src-tauri/src/stitch/`），前端只负责显示。

### 4.1 基本思路

假设向下滚动。新帧的**顶部**一定和已拼图的**底部**有重叠区域。找到这段重叠，把新帧重叠部分以下的内容追加上去。

```
已拼好的图                   新采集的帧
┌──────────┐                ┌──────────┐
│          │                │ ▓▓▓▓▓▓▓▓ │ ← 这部分和已拼图的底部相同
│          │                │ ▓▓▓▓▓▓▓▓ │
│          │                ├──────────┤
│ ▓▓▓▓▓▓▓▓ │ ← 重叠区        │          │ ← 只有这部分是新内容
│ ▓▓▓▓▓▓▓▓ │                │          │
└──────────┘                └──────────┘
```

### 4.2 算法步骤

```rust
/// 返回新帧中「新内容的起始 y 坐标」，None 表示匹配失败
fn find_overlap(
    prev_bottom: &GrayImage,   // 已拼图底部的一条，高度 = SEARCH_BAND
    curr: &GrayImage,          // 新帧（灰度）
    fixed_header_h: u32,       // 已识别的固定头部高度
) -> Option<u32>
```

**步骤 1 · 预处理**
- 两张图都转灰度（`image::imageops::grayscale`）
- 若选区宽度 > 800px，横向下采样到 800px（加速，精度足够）

**步骤 2 · 选取模板条**
- 从已拼图的底部取 `TEMPLATE_H = 40` 行像素作为模板
- 若这 40 行的**方差极小**（纯色区域，如空白页面底部），说明没有特征，向上滑动取样，最多向上找 5 次（每次上移 40 行）。全都是纯色则匹配失败

**步骤 3 · 滑窗匹配**
- 在新帧中，从 `y = fixed_header_h` 开始，逐行向下滑动模板，计算相似度
- 搜索范围上限：`min(frame_height - TEMPLATE_H, MAX_SEARCH)`，`MAX_SEARCH = frame_height`（全帧搜索，因为用户可能滚得很少或很多）
- 相似度用**归一化互相关（NCC）**：

```
NCC(y) = Σ[(T(i,j) - T̄)(F(i, y+j) - F̄_y)]
         ────────────────────────────────────
         √(Σ(T(i,j) - T̄)²) · √(Σ(F(i,y+j) - F̄_y)²)
```

- 也可以先用**绝对差和（SAD）**做粗筛（快得多），取 SAD 最小的前 5 个位置，再对这 5 个算 NCC 精确比较。推荐这个两阶段方案

**步骤 4 · 判定**
- 取 NCC 最大的位置 `y_best`，分数 `score_best`
- `score_best >= 0.92` → 匹配成功，新内容从 `y_best + TEMPLATE_H` 开始
- `score_best < 0.92` → 匹配失败
- 若 `y_best + TEMPLATE_H >= frame_height - 4` → 判定为"到底了"（用户滚不动了，新帧和上一帧几乎完全一样）

**步骤 5 · 追加**
- 把新帧从 `y_best + TEMPLATE_H` 到底部的内容追加到长图
- 若新增高度 < 4px，视为"没滚动"，忽略这一帧（不报错，也不追加）

### 4.3 固定头部/尾部识别

网页的悬浮导航栏、软件的固定工具栏，在每一帧的同一位置都是一样的，不处理会在长图里重复出现很多次。

**头部识别**（在采集到第 3 帧时执行一次，之后不再重算）：

```
比较第1、2、3帧的顶部区域：
for h in (0..frame_height/3).rev().step_by(4):
    if 三帧的 [0..h] 区域两两像素差异 < 阈值:
        fixed_header_h = h
        break
```

阈值：平均绝对差 < 2（0–255 灰度）。

识别到固定头部后：
- 第 2 帧起，拼接时的搜索起点设为 `fixed_header_h`
- 追加到长图时，若新内容的起点小于 `fixed_header_h`，说明重叠区跨过了头部，把 `[0..fixed_header_h]` 裁掉

**尾部识别**同理，检测底部区域。尾部（如固定的输入框、底部导航）在**最终成图时**只保留最后一帧的那一份，中间帧的都裁掉。

⚠ 头部识别有误判风险：如果页面顶部本来就是一大片空白，会被误判成固定头部。缓解：要求固定头部高度 ≥ 16px 且该区域的**方差 > 阈值**（不是纯色），否则不认。

### 4.4 内存管理

一张 1080 宽 × 32000 高的 RGBA 图 = 138 MB。必须控制：

- 长图**不在内存里以完整 RGBA 保存**。维护一个 `Vec<FrameSlice>`，每片记录 `{ frame_index, src_y_start, src_y_end }`，帧图像存磁盘临时文件
- 只在最终合成时按顺序读盘拼出完整图
- 预览缩略图单独维护一份小的（宽 120px）
- **硬上限 32000px**。达到上限提示用户结束，再滚不再采集。这也是 PNG 在多数看图软件里能正常打开的实践上限
- 会话结束或放弃时立即清理临时文件

### 4.5 单元测试（必须写）

在 `src-tauri/src/stitch/tests.rs` 里，用程序生成的测试图验证：

1. 完美重叠：造一张 1000px 高的图，切成三段各有 200px 重叠，拼回去应完全等于原图
2. 有固定头部：每帧顶部加 60px 相同的色块，拼接后长图里该色块只出现一次
3. 纯色区域：帧内容全白，应返回匹配失败而不是 panic
4. 到底了：连续两帧完全相同，应返回 `ReachedBottom`
5. 滚动量大于一屏（中间有内容丢失）：应返回匹配失败
6. 横向下采样后的坐标换算正确

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 用户往回滚（向上） | 允许。检测到新帧内容在已拼图的**上方**（在已拼图顶部找到匹配），则往上追加。这让用户可以从中间开始往两头滚 |
| 用户滚太快，跨过一整屏 | 匹配失败 → 黄色提示"请往回滚一点再试"。用户往回滚后能接上 |
| 内容有动画（GIF、视频） | 匹配大概率失败。提示条给出建议文案"页面有动态内容，尝试暂停后再滚" |
| 用户滚动时切换了窗口 | 采集到的帧会是另一个窗口的内容 → 匹配失败 → 提示 |
| 采集过程中选区所在窗口被移动 | 无法检测，用户自己负责。文档里说明 |
| 只采集了 1 帧就按 Enter | 等同于普通截图，直接出图 |
| 采集了 0 帧就按 Enter | 提示"还没有采集内容" |

## 7. 完成后的处理

1. 按 `slices` 顺序读盘合成完整图，写到临时 PNG
2. 关闭采集窗口，打开一个**长图编辑窗口**（不是原来的全屏遮罩）
   - 尺寸：宽 = min(图宽 + 边距, 屏宽 × 0.8)，高 = min(图高, 屏高 × 0.85)
   - 图片可垂直滚动查看
   - 复用 02 的标注工具（矩形/椭圆/箭头/画笔/马赛克/文字）
   - 工具条固定在窗口底部，不跟随选区
   - 额外提供：识字、翻译、保存、复制
3. 超大图复制到剪贴板可能失败（部分应用有大小限制），若图高 > 8000px，默认动作改为"保存"并提示
