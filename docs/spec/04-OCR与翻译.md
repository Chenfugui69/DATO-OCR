# 第一部分 · OCR 文字识别

## 1. 引擎选型

| | RapidOCR（默认，内置） | PaddleOCR（可选，用户下载） |
|---|---|---|
| 部署体积 | 30 MB | 250 MB |
| 初始化 | < 0.1 秒 | 约 2 秒 |
| 单张识别 | 中等（1080p 截图约 0.4–0.8 秒） | 快（约 0.2–0.4 秒） |
| 内存峰值 | ~500 MB | > 2 GB（启用 mkldnn） |
| CPU 要求 | 无 | **必须支持 AVX 指令集**。Atom / Celeron / Pentium 不可用 |
| 精度 | 印刷体优秀，手写体一般 | 手写体、艺术字、小字明显更好 |
| 协议 | Apache-2.0 | Apache-2.0 |

**默认内置 RapidOCR。** 理由：体积是核心诉求，且它对老机器友好，不会出现"装了用不了"。

设置里提供「下载高精度引擎」入口，用户点击后下载 PaddleOCR 到 `%APPDATA%/DATO COR/engines/paddle/`。下载前必须**检测 CPU 是否支持 AVX**，不支持则灰掉按钮并说明原因。

## 2. 集成方式

两个引擎都以 **sidecar 子进程**形式运行，通过 stdin/stdout 交换 JSON。

- RapidOCR 走 Tauri 的 `externalBin`（打包时随安装包分发）
- PaddleOCR 走用户数据目录（运行时下载）

```
src-tauri/resources/ocr/
├── RapidOCR-json.exe
└── models/
    ├── ch_PP-OCRv4_det_infer.onnx
    ├── ch_ppocr_mobile_v2.0_cls_infer.onnx
    ├── ch_PP-OCRv4_rec_infer.onnx
    └── ppocr_keys_v1.txt
```

⚠ **打包前必须删掉 models 目录里除中英文以外的所有 `*_rec_infer` 文件**，每组约 10 MB。

### 2.1 进程生命周期

```rust
pub struct OcrManager {
    child: Mutex<Option<OcrProcess>>,
    engine: RwLock<EngineKind>,
    idle_timer: ...,
}
```

规则：

1. **懒启动** —— 应用启动时不拉起 OCR 进程，第一次识别请求时才启动
2. **常驻复用** —— 启动后保持进程存活，后续请求直接复用（避免每次 2 秒的初始化）
3. **空闲回收** —— 连续 5 分钟无请求，杀掉进程释放内存。设置里可配（1/5/15 分钟/永不）
4. **崩溃自愈** —— 检测到子进程退出，下次请求时自动重启，最多连续重启 3 次，之后报错
5. **应用退出时必须杀掉子进程**，防止残留

### 2.2 通信协议

RapidOCR-json 的协议：启动时读一行配置 JSON，之后每行输入一个任务，每行输出一个结果。

请求：
```json
{"image_path": "C:\\Users\\x\\AppData\\Local\\Temp\\chenocr\\ocr_input.png"}
```

也支持 base64（`{"image_base64": "..."}`）和剪贴板（`{"image_path": null}`）。

**统一用临时文件路径**，不用 base64。base64 在大图时会让 stdin 缓冲区爆掉。

响应：
```json
{
  "code": 100,
  "data": [
    { "box": [[12,8],[210,8],[210,36],[12,36]], "score": 0.98, "text": "识别到的文字" }
  ]
}
```

`code` 含义：`100` 成功、`101` 无文字、其他为错误。**`101` 不是错误**，要区分对待，给用户显示"没有识别到文字"而不是报错。

### 2.3 超时与取消

- 单次识别超时 15 秒，超时则杀进程重启并报错
- 前端有取消按钮，取消时向 Rust 发信号，Rust 直接丢弃结果（不杀进程）

## 3. 段落重组

**这是决定体验好坏的关键一步，不能省。**

引擎返回的是一堆零散的文本框。直接把 `text` 拼起来会得到断行混乱、无法阅读的结果。必须重组。

### 3.1 算法

```rust
pub fn reflow(blocks: &[OcrBlock]) -> Vec<Paragraph>
```

**步骤 1 · 归一化**
每个 block 的 `box` 是四个点（可能是倾斜的），转成轴对齐包围盒 `{ x, y, w, h }`，并记录中心点和倾角。

**步骤 2 · 行聚类**
按 `y` 排序。两个 block 属于同一行的条件：

```
垂直重叠率 = 重叠高度 / min(h1, h2) > 0.5
```

用垂直重叠率而不是"中心 y 差值 < 阈值"，因为字号可能不同。

同一行内的 block 按 `x` 排序。

**步骤 3 · 行内拼接**
决定两个相邻 block 之间放什么：

```
gap = next.x - (curr.x + curr.w)
avgCharWidth = curr.w / curr.text.chars().count()

if gap < avgCharWidth * 0.3      → 直接连接，不加任何字符
if gap < avgCharWidth * 2.0      → 加一个空格（西文）或不加（中文）
else                             → 视为同一行的两列，用 "\t" 分隔（表格场景）
```

判断中西文：看两侧字符是否为 CJK。中文之间不加空格，西文之间加。

**步骤 4 · 段落聚类**
相邻两行属于同一段的条件（全部满足）：

```
1. 行间距 <= 上一行高度 * 1.6
2. 上一行的右边缘接近段落的最右边界（说明是被撑满而换行，不是主动断行）
   |line_prev.right - block_right_edge| < avgCharHeight * 2
3. 两行的左边缘对齐，或下一行左边缘缩进（首行缩进）
   |line_curr.left - line_prev.left| < avgCharWidth * 4
```

不满足则开新段。

**步骤 5 · 输出**

```ts
interface Paragraph {
  text: string;              // 段落全文，行内已合并
  lines: Line[];             // 保留行结构，供高亮联动用
  bbox: Rect;                // 整段的包围盒
  blockIndices: number[];    // 对应原始 block 的下标
}
```

同时输出两种纯文本：

- `plainText` —— 段落之间 `\n\n`，段落内不换行。**这是默认复制的内容**
- `rawText` —— 保留原始每行换行。设置里可选

### 3.2 单元测试

用固定的 block 数组（手写几组 JSON 测试数据）验证：

1. 单段落多行的中文，重组后段内无换行
2. 两段之间正确断开
3. 中文之间不加空格，英文单词之间加空格
4. 双栏排版被正确识别为两个独立列（不要把左右两栏的文字串在一起）
5. 表格场景，同行不同列用 tab 分隔

⚠ **双栏识别**是个加分项，实现方式：先对所有 block 的 x 中心做一维聚类，若明显分成两簇且两簇之间有一条纵向的空白带（宽度 > 平均字宽 × 3），则拆成左右两栏分别处理，最后左栏全部在前、右栏在后。第一版可以先不做，但要在代码里留 TODO。

### 交互要求

- [ ] 左右分栏，可拖动中间分隔条调整比例
- [ ] 鼠标悬停右侧某个段落 → 左侧对应区域高亮（主色 12% 填充 + 1px 主色边框）
- [ ] 鼠标悬停左侧某个文字区域 → 右侧对应段落高亮，并自动滚动到可见
- [ ] 右侧文字可直接编辑（识别有错时改一下再复制）
- [ ] 右侧文字可选择，选中后有浮动小工具条：复制 / 翻译 / 搜索
- [ ] 「复制全部」复制的是当前编辑框里的内容（含用户的修改）
- [ ] 「重新识别」下拉：切换引擎重试 / 提高分辨率重试（把图放大 2 倍再识别，对小字有效）
- [ ] 置信度筛选：可以隐藏置信度低于某阈值的结果（默认不筛选）
- [ ] 图片支持滚轮缩放、拖动平移，双击复原
- [ ] Ctrl+C 复制全部，Ctrl+W 关闭

# 第二部分 · 翻译

## 6. 翻译源

多源自动降级。按顺序尝试，失败或超时（5 秒）则换下一个。

### 6.1 内置免费源（无需配置，开箱可用）

| 优先级 | 源 | 说明 | 风险 |
|---|---|---|---|
| 1 | **有道翻译（网页接口）** | 国内可直连，速度快，中英质量好 | 接口可能变更，需要处理签名 |
| 2 | **Bing 翻译（网页接口）** | 需先取一次 token，之后可用一段时间 | 国内可访问 |
| 3 | **Google 翻译（`translate.googleapis.com/translate_a/single`）** | 无需密钥，质量最好 | **国内直连不通**，仅对能访问的用户有效 |

⚠ 这三个都是**非官方接口**，随时可能失效。所以：

- 必须做**失败自动降级**，一个不行立刻换下一个
- 必须把接口地址和签名逻辑**收敛到一个文件** `src-tauri/src/translate/providers/`，一个 provider 一个文件，方便随时替换
- 全部失败时，给用户明确提示"内置翻译暂时不可用，可在设置中填写自己的翻译密钥"，并给一个跳转到设置的按钮
- 请求要带合理的 `User-Agent`，加 3 秒的最小间隔限流，不要把接口打爆

### 6.2 用户自配源（设置里填密钥）

| 源 | 需要什么 | 说明 |
|---|---|---|
| DeepL | API Key | Free 版每月 50 万字符免费。质量最好 |
| OpenAI 兼容 | Base URL + API Key + 模型名 | 支持 OpenAI 官方、DeepSeek、通义、Kimi 等所有兼容接口 |
| 自定义 HTTP | URL 模板 + 请求体模板 | 高级用户自己接任何服务 |

用户配了自定义源之后，它自动成为**最高优先级**。

**OpenAI 兼容源的提示词**（写死在代码里，不暴露给用户）：

```
System: You are a translation engine. Translate the user's text into {target_language}.
Output ONLY the translation, no explanations, no quotes, no markdown.
Preserve the original line breaks and paragraph structure.
If the text is already in {target_language}, translate it into English instead.

User: {text}
```

### 6.3 密钥存储

**API Key 绝不能明文存在配置文件里。**

用 Windows 的 DPAPI（`CryptProtectData`）加密后存数据库。DPAPI 用当前用户账户作为密钥，其他用户/其他机器解不开。

```rust
// src-tauri/src/platform/windows/secret.rs
pub fn protect(plain: &[u8]) -> Result<Vec<u8>>;
pub fn unprotect(cipher: &[u8]) -> Result<Vec<u8>>;
```

macOS 移植时对应 Keychain。

界面上密钥输入框只显示 `sk-••••••••1234`（前 3 后 4），点"显示"才明文。

## 7. 语言检测

先本地判断，减少一次网络请求：

```
中日韩字符占比 > 20%  → 进一步区分 zh / ja / ko（看假名、谚文）
西里尔字符占比 > 20%  → ru
阿拉伯字符           → ar
泰文字符             → th
默认                 → en
```

检测结果只是**默认值**，界面上用户可手动改。

**默认目标语言规则**：源语言是中文 → 译成英文；源语言是其他 → 译成中文。设置里可改。

## 8. 翻译界面

### 8.1 从截图/识字进入

识字窗口点「翻译」，右侧文字区域**分成上下两栏**：上面是原文，下面是译文。不开新窗口。

```
┌───────────────────────────────────┐
│  原文 · 英语 ▾                     │
│  ┌─────────────────────────────┐  │
│  │ The quick brown fox...      │  │
│  └─────────────────────────────┘  │
│              ⇅ 交换                │
│  译文 · 中文 ▾      有道 ▾         │
│  ┌─────────────────────────────┐  │
│  │ 敏捷的棕色狐狸...            │  │
│  └─────────────────────────────┘  │
│                    [复制译文]     │
└───────────────────────────────────┘
```

- 译文区加载中显示骨架屏（三条灰色横线的呼吸动画），不要用转圈
- 右上角显示当前用的是哪个源，可下拉切换手动指定
- 切换源后立即重新翻译

### 8.2 划词翻译（独立功能）

- 快捷键 `Ctrl+Alt+T`：读取当前选中的文本（通过模拟 Ctrl+C 后读剪贴板，读完恢复原剪贴板内容），在鼠标附近弹出一个小的翻译气泡
- 气泡：最宽 420px，玻璃材质，圆角 12px，有指向鼠标位置的小尖角
- 点击气泡外部或按 Esc 关闭
- ⚠ 模拟 Ctrl+C 会污染剪贴板，必须在读完后立即恢复原内容，且这次变化不要写入剪贴板历史（在剪贴板监听里加一个"忽略下一次变化"的标记）

### 8.3 剪贴板里翻译

剪贴板面板中，文本卡片右键 →「翻译」，在卡片下方原地展开译文，不跳窗口。

## 9. 缓存

同一段文字 + 同一目标语言 + 同一源 = 直接返回缓存，不发请求。

- 缓存键：`sha256(text)[..16] + target_lang + provider`
- 存内存 LRU，容量 200 条
- 应用重启后清空（不持久化，避免占用数据库）

## 10. M3 验收标准

### OCR
- [ ] 首次识别（含引擎启动）< 3 秒，后续识别 < 1 秒
- [ ] 识别一张微信聊天截图，段落分行正确，能直接粘贴使用
- [ ] 识别一段代码截图，缩进和换行合理
- [ ] 识别一张纯图片（无文字），提示"没有识别到文字"而不是报错
- [ ] 5 分钟不用后，任务管理器里看不到 OCR 子进程
- [ ] 杀掉 OCR 子进程后再次识别，能自动恢复
- [ ] 退出 DATO COR 后，无残留子进程
- [ ] 段落重组的 5 个单元测试通过
- [ ] 在不支持 AVX 的 CPU 上（可用虚拟机模拟），RapidOCR 正常工作，PaddleOCR 下载按钮为灰色并有说明

### 翻译
- [ ] 不做任何配置，开箱能翻译中英互译
- [ ] 断网时给出明确错误提示，不是无限转圈
- [ ] 第一个源失败时，自动切到第二个，用户无感知（可在日志里看到切换记录）
- [ ] 配置 DeepL 密钥后，优先使用 DeepL
- [ ] API Key 在配置文件和数据库里都是密文
- [ ] 划词翻译后，原剪贴板内容完好无损，且剪贴板历史里没有多出一条记录
- [ ] 同一段文字连续翻译两次，第二次瞬间返回（命中缓存）
