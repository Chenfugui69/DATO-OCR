### M0 退出前必须补齐（不允许带进 M1）

这两条是补债，不是新功能。M0 期间为了快速验证技术路线跳过了，进 M1 之前必须做完。

- [ ] **ESLint 配置**（`eslint.config.js` 从未存在，`pnpm lint` 一直是直接报错退出）。至少启用：
  - `@typescript-eslint/no-floating-promises`（需开类型感知 `projectService`）
  - `@typescript-eslint/no-misused-promises`
  - `react-hooks/exhaustive-deps`

  这三条对应的都是本项目 M0 期间**已经真实发生过**的静默失败：未 await 的 IPC 调用把错误吞掉、`useEffect` 漏依赖导致遮罩状态不同步。

- [x] **Clippy 配置**已补。00 §6.2 那条"禁止 unwrap/expect"靠人工 review 守不住，现在由 lint 拦：
  ```rust
  #![deny(clippy::unwrap_used, clippy::expect_used)]
  #![cfg_attr(test, allow(clippy::unwrap_used, clippy::expect_used))]
  ```
  测试代码整体放行 —— 断言失败就该 panic，改成 `?` 只会让失败信息变差。注意
  `cfg_attr(test, ..)` 是整个 crate 放行，所以生产代码的拦截发生在**非 test** 那次
  编译上；`cargo clippy --all-targets` 两次都编，覆盖是完整的。

  22 处命中里 20 处在测试代码，按上面的方式放行、**一个都没改**。生产代码那 2 处
  是真改掉的，没有用 `#[allow]` 绕：

  | 位置 | 原来 | 现在 |
  |---|---|---|
  | `capture/protocol.rs` | `Response::builder().body().expect()` | 改用 `Response::new()` + `status_mut()`，这条路径没有 `Result` |
  | `lib.rs` | `.build().expect("初始化失败")` | 改成 `match` + 写日志 + `exit(1)` |

  第二处顺带修了一个真问题：这是 `windows_subsystem = "windows"` 的 GUI 进程，
  没有控制台，panic 信息直接进虚空 —— 初始化失败时用户看到的是"双击了没反应"，
  而我们手里一条线索都没有。现在至少会往日志里留一笔。

  验证过 lint 真的生效（配错了的 lint 比没有 lint 更危险）：往生产代码里塞一个
  `unwrap()`，`cargo clippy` 报 `error: used unwrap() on a Result value` 并中止编译。

### 自动化验收脚本

M0 期间攒下来的，不属于产品代码，但后续里程碑的回归要接着用：

| 脚本 | 验什么 |
|---|---|
| `scripts/measure-m0.ps1` | 分段耗时：抓屏 / 编码 / 传输 / 解码 / 首帧 |
| `scripts/verify-backdrop.ps1` | 底图是冻结的 + 与真实桌面逐像素一致 + 置顶窗口不会从选区里浮出来 |
| `scripts/probe-zorder.ps1` | 直接读底图窗口的 `GWL_EXSTYLE` 和 z 序邻居，验波段归属 |
| `scripts/verify-rewarm.ps1` | 热身失效后会自动重新热身（含监听窗口够不够格收广播） |
| `scripts/verify-clipboard.ps1` | 剪贴板图片尺寸精确 + alpha 正确 |
| `scripts/shoot-overlay.ps1` | 把遮罩截下来人眼看 |
| `scripts/lib.ps1` | 公共部分：清残留进程、查热键是否注册上、设环境变量 |

写这类脚本有三个反复踩到的坑，都已经写进各脚本的注释：

1. **必须声明 PMv2**，否则量出来的坐标和尺寸全是被系统虚拟化过的（150% 屏上
   400×300 会量成 600×450）。
2. **必须存 UTF-8 BOM**，否则 PowerShell 按 ANSI 解释中文注释，报
   `MissingEndCurlyBrace` 这种完全误导人的语法错。
3. **比对类脚本在"取基准"和"触发冻结"之间不能让屏幕有任何变化**，连一句
   `Write-Host` 都不行 —— 它会滚动终端，而比对区往往就压在终端上。输出要攒到
   比对结束后再打。这一条曾让 `verify-backdrop.ps1` 时过时不过，白查半天产品代码。
   同理，这类脚本必须带**对照组**（先证明"该被看到的东西确实能被抓到"），
   否则它可能因为根本没生效而假过。
4. **对抗性测试要选对对手，否则测了等于没测。** 验"有没有窗口能从选区里浮出来"
   这件事上踩了两次：
   - 用**普通窗口**当入侵者：它永远在非 topmost 波段，压根到不了遮罩下方那个
     夹层，所以无论产品对错都会「通过」。
   - 冻结**之后**才把它设成 `HWND_TOPMOST`：那会插到 topmost 波段最顶上，连遮罩
     一起盖住，所以无论产品对错都会「失败」。任何截图工具都拦不住这种情况。

   有意义的只有一种：置顶窗口在按 F1 **之前**就存在，冻结后只挪位置、
   **不动 z 序**（`SWP_NOZORDER`）。

### 如果失败

**不要硬撑。** 立即汇报是哪一条失败、失败现象、排查过的方向。掉头到 Electron 的成本在这个阶段最低。

## 缺陷分级

汇报问题时按这个分级：

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 崩溃、数据丢失、核心功能完全不可用 | 立即停下修 |
| P1 | 核心功能在特定环境下不可用、性能红线超标 | 本阶段内必须修完 |
| P2 | 次要功能有问题、视觉不符合规范 | 可以推到 M6 统一处理 |
| P3 | 体验优化建议 | 记录到 backlog，第一版不做 |

## 第一版明确不做的事

写下来是为了防止范围蔓延：

- Apple 账户登录（第二阶段）
- iPhone 剪贴板同步、验证码转发（第二阶段）
- 云端同步、多设备（第二阶段）
- macOS 版本（只留抽象层，不实现）
- Linux 版本
- 自动滚动长截图（已决定只做手动）
- 录屏、GIF 录制
- 图床上传、生成分享链接
- 屏幕标注（不截图，直接在屏幕上画）
- 插件系统
- OCR 表格还原成 Excel
- 手写公式识别
- 云端 OCR（只做本地 + 可选下载高精度本地引擎）
- 英文界面（文案要写，但第一版只出中文包）
