# DATO OCR 实现交接

> 品牌改过两次名（2026-10）：CHENOCR → DATO COR → **DATO OCR**。数据目录在启动时自动从旧名字搬到 `%APPDATA%\DATO OCR`（`paths.rs`）；
> 用默认保存位置的，`图片\DATO COR` 也跟着改名（`capture::migrate_save_directory`）；旧名字的开机自启项会删掉、按设置用新名字重新登记（`lib.rs` `after_rename`）；
> 从 0.3.0（产品名还叫 DATO COR）升级上来，安装包装完会静默卸掉旧的那份（`src-tauri/windows/hooks.nsh`）。
> 内部代号都没改：crate、`chenocr.exe`、`chenocr.db`、`CHENOCR_*` 环境变量、密钥盐值、应用标识 `com.datocor.app`（改了 WebView 数据、单实例、开机自启都会错位）、
> 同步协议里的 `dato-cor/...` 标签和 mDNS 服务名 `_datocor._tcp`、更新签名私钥文件名 `dato-cor-updater.key`。

> 写给下一个接手实现的人（或 AI）。先读这份，再读 `docs/spec/00-项目总纲.md`。
> 本文只记**代码里看不出来**的东西：进度、和规格不一样的地方、删了会出事的代码、踩过的坑、怎么测。

## 3. 不能删的东西

这些代码看着多余或绕，删了会出现**很难复现**的问题。

### 截图

- **遮罩窗口启动时预建并隐藏**（`capture/overlay.rs` `prewarm`）。WebView2 首次创建要 400ms+，放到热键之后必然超 150ms 预算。插拔屏后会重建。
- **冻结底图是原生分层窗口，不是 WebView 里的图**（`platform/windows/backdrop.rs`）。和透明遮罩用 `DeferWindowPos` 原子上屏（`overlay::show_with_backdrop`）。把 4K 底图送进 WebView 实测 244ms。
- **底图像素照样通过 `shot:` 协议流进 WebView**（`image_store.rs`），给放大镜、取色、马赛克用。编码是 24bpp BMP —— 桌面截图编 PNG 又慢又大。
- **抓屏预热 + 失效后重新预热**（`platform::warm_up_capture`、`lib.rs` `on_system_event`）。首次抓屏要建 D3D 设备，比后续慢 ~90ms；插拔屏、睡眠唤醒后又会失效。
- **所有浮动窗口隐藏时也要设 `WDA_EXCLUDEFROMCAPTURE`**（`platform/windows/effects.rs`）。实测本进程用 WGC 抓屏时，没排除的**隐藏**窗口会被画成带标题栏的白块。诊断模式 `CHENOCR_ALLOW_SELF_CAPTURE=1` 也只在窗口**显示期间**放开（`reveal_for_tests`）。
- **选区一律存本屏局部物理像素**，只在渲染时换算 CSS 像素。
- **子控件在遮罩出现之前、和抓屏并行枚举好**（`capture::enumerate_for_detection`），随会话下发给前端。Chromium 系浏览器（Edge、Chrome、Electron 应用）发现窗口被完全遮住，会把网页内容区那个 `Chrome_RenderWidgetHostHWND` 子窗口藏起来；遮罩盖上之后再去查，就只剩整个浏览器窗口可框。

### GIF 录制

- **录屏用 xcap 的 WGC 连续录制**（`platform::ScreenRecorder`），不是每帧调一次抓屏：单次抓屏要新建会话，4K 一帧 60～70ms，到不了 15fps。
- **不装全局键盘钩子**（`gif_record.rs`）：录的就是用户的操作，回车、Esc、退格都得照常给目标程序；长截图那个钩子会吞掉这三个键，不能复用。
  结束靠控制条按钮或再按一次截图热键（前端收到 `capture-hotkey` 转发后调 `gif.finish`）。
- **控制条能点靠录制线程每一拍查一次鼠标位置**，在控制条上就关掉遮罩的鼠标穿透（和长截图同一个思路，只是不用钩子）。
- **增量编码**：只编码和上一帧相比变了的矩形，块里没变的像素设成透明，`DisposalMethod::Keep` 让上一帧留着；完全没变就不出帧，上一帧自动拉长。编码跟不上时录制那边丢帧（`QUEUE`），不会越积越多。
- **调试版只有 3fps 左右**（未优化的 NeuQuant 量化、4K 帧格式转换都很慢），量帧率要用正式版。
- 测试时设 `CHENOCR_TEST_NO_CLIPBOARD=1` 不往剪贴板写 GIF 文件（测试机的远程控制软件会把剪贴板同步到别的电脑）。

### 截图遮罩和工具条（2026-10-08 这一批）

- **贴图窗口先藏着建，页面把图画出来才显示**（`pin::create` / `pin::ready`，页面在图片 `onLoad` 后调 `pin_ready`，1.5 秒兜底）。从截图工具条点贴图时，遮罩等到这一刻才收（`capture::finish` 里 `on_ready` 才 `end_session`）。以前是先收遮罩再建窗口，选区那块画面消失两三百毫秒又冒出来，加上出现时的缩放动画，看着"跳一下"。出现动画也去掉了。实测点下去约 200ms 贴图窗口显示，遮罩紧跟着收。
- **拖柄从开始拖选区就显示**（`selecting` 阶段也画 `Handles`），不是松手才出现。
- **选区框多了一种"四角"线型**（`FrameStyle.style = "corners"`，`FrameBox` 的 `bracketRing`）：只画四个角，每个角是圆弧带两条短臂；这种样式不叠拖柄。识字框默认用它（白色 3px、圆角 24）。旧设置里还是老默认（白色实线圆角 12）的识字框会自动换一次，靠 `capture.extra.ocrFrameCorners` 记着换过了。
- **工具条三组按钮的顺序都能调**：`capture.toolbar_tools`（绘制工具）、`toolbar_actions`（识字 / 翻译 / 问 AI / 长截图 / GIF）、`toolbar_order`（默认 撤销、保存、贴图、取消、完成）。设置页"截图"里画了一条和真工具条一样的条（`ToolbarOrder.tsx`），按住图标左右拖，只能在自己那一组里换；自己跟指针，不用 HTML5 拖放（Tauri 窗口接管了拖放）。真机拖过：顺序写进设置、能拖回来。图片编辑器用同一份顺序（没有长截图和 GIF）。撤销按钮属于最右边那一组。
- **长截图、GIF 的图标是自己画的**（`Toolbar.tsx` 的 `LongshotIcon` / `GifIcon`）：原来识字、长截图、GIF 三个都是"方框里几道线"，用户经常点错。现在长截图是一页内容旁边一根上下滚动的箭头，GIF 是方框里用线条写的 G、I、F —— 都按 lucide 的画法（同样粗细的线条、占位接近正方形）。试过纯文字的"GIF"，用户说没有外框、不是线条画的，看着像单独贴上去的；图标要先出几个样子给用户挑。改图标时在设置页那条预览里看效果最快。
- **截图识字 / 翻译不自动框窗口**（`hoverAt`）：整屏均匀压暗（默认 20%），等用户自己拖；单击不算数。识字要的是一小段文字，自动框出来的整个窗口几乎从来不是想要的范围。
- **长截图截完自动复制到剪贴板**（`longshot::finish`），编辑窗口照样打开。
- **默认值**：屏幕压暗 40%、选区框 3px、识字框见上；翻译源顺序 有道、必应、谷歌、腾讯；划词面板宽 380、毛玻璃开、不透明度 0.45；剪贴板底部横向、不贴边。只影响新装和"恢复默认"，已有设置不动（识字框那一项除外）。
- **没在真遮罩上看过**：遮罩窗口排除了抓屏，脚本截不到。四角框和新图标是按同样的 CSS / SVG 在浏览器里单独渲染看的；拖动时的拖柄、工具条新顺序只过了类型检查，要真人看一眼。

### 长截图

- **滚动时连续拍，不是滚一下停一下**（偏离规格 03 §3.2 的"防抖 160ms 再拍一帧"）。听到滚轮就开一轮（`longshot/mod.rs` `round`）：用 GIF 那个连续抓屏（`ScreenRecorder`）一帧接一帧地喂给拼接器，滚轮停了、画面也不动了（设置里的"停稳判定"，默认 160ms）再单独抓一张收尾。用户可以一口气从头滚到底。
- **跟踪和并入分开**（`stitch.rs` `feed`）。每帧都算位移，但攒够三分之一屏新内容或停稳时才并入、才存原图；没并入的那帧由 `Active.held` 拿着，拼接器说要留（`keep_prev`：跟丢了、往回滚了、再滚就脱节了）才存。别改回每帧都并入：一次长截图会存几百张原图。
- **撤销按"轮"算**：每轮滚动开始记一个撤销点（`Stitcher::checkpoint`），Backspace 退掉一整轮。`Progress.frames` 现在是"1 + 带来新内容的轮数"，界面只用它判断"还没开始"和撤销按钮能不能点。
- **搜索先比每行灰度和再算 SAD、先找上一次的方向**：连续采集每帧都要算，原来两个方向各试 8 个模板位置要一两百毫秒。现在正式版一帧 2.6ms（1000×1100 选区）。
- 真机量过（`cargo test --profile perf -- --ignored smoke_continuous`，目标 `scrollwin.ps1`，7 秒里连滚 130 格再回滚 15 格）：55 帧/秒，跟丢 0 次，387 帧只存 41 帧，15621px 长图 340 行逐行连续。应用里也跑过（`--action=longshot` 驱动 dev 实例，同样的连滚）：4 秒 219 帧，跟丢 0 次，10201px。每轮滚动结束会打一行日志"长截图：一轮滚动结束"（帧数、跟丢几帧、等帧/拼接/刷预览各花多久、单帧最多滚了多少行），有人说跟不上先看它。
- **调试版也开了优化**（`Cargo.toml` `[profile.dev]`：自己的代码 1、依赖 3）。不开的话 4K 屏连续抓屏一帧 220ms、拼接一帧 100ms，一秒不到 3 帧，`tauri dev` 里一滚就跟丢（2026-10-07 用户就是这样试出"还是跟不上"的）。别关。
- **连续抓屏一进长截图就开好**（`start_recorder`），不等第一下滚轮：开会话要一百来毫秒，这期间页面已经滚走了。

- **进入采集后把焦点交给选区中心下面的窗口**（`longshot/mod.rs` `start` 里的 `platform::window_at`）。不交的话焦点留在遮罩上，滚轮全发给遮罩，页面纹丝不动。用 `WindowFromPoint` 现取（此时遮罩已穿透、底图已隐藏），不用窗口枚举 —— 枚举会把 DATO OCR 自己的窗口滤掉，选区落在 DATO OCR 主窗口上时会找错。
- **遮罩默认鼠标穿透，鼠标移进提示条 / 预览条时才临时关掉穿透**（`update_interactive`），移出时把焦点还给目标窗口。
- **Enter / Esc / Backspace 走全局低级键盘钩子**，因为穿透的遮罩拿不到键盘焦点。
- **滚轮停后补拍到画面不动为止**（`MAX_SETTLE_STEPS`），**完成时也先补拍**。浏览器、RichEdit、WinUI 都是平滑滚动，滚轮事件停了画面还在动；不补拍，最后一屏会漏掉（实测漏过 7 行）。
- **帧原图存临时目录，内存里只放缩略图**。50 帧全放内存会超规格的 200MB 增长上限。
- **重叠区复核按"有纹理的小块"算、只要求大部分对上**（`stitch.rs` `verify`），**模板对不上就换位置、换半边再试**（`find_shift`）。网页图片是懒加载的，上一帧的灰色占位块下一帧就成了封面；要求重叠区处处一致的话，在视频站上几乎每帧都失败，而且失败后再也接不上（只能和最后一张成功的帧比）。
- **并入新帧时以新帧为准**：新帧覆盖它和已有内容重叠的那段。长图里留下的是加载好的样子，视口里固定的悬浮按钮也只出现一次。
- **连续两次滚轮画面都没动才提示"到底了"**。无限滚动的页面加载下一批时会停一下，提示太早用户会以为滚不动了。

### 识字

- **资源路径要去掉 `\\?\` 前缀**（`paths.rs` `strip_verbatim`），**引擎工作目录设成引擎目录、模型用相对路径**（`ocr/rapid.rs`）。Tauri 给的资源路径带 `\\?\`，RapidOCR-json 读不到模型，表现是"启动后立即退出"。
- **子进程放进"句柄关闭即全杀"的作业对象**（`platform/windows/process.rs` `tie_to_current_process`）。正式版是 `panic = "abort"`，崩溃不走退出流程；没有它，主进程一崩识字引擎就成了孤儿进程。
- **PaddleOCR 是可选下载**（`ocr/paddle.rs`）：PaddleOCR-json v1.4.1（Apache-2.0，和 RapidOCR-json 同一个作者、同一套 JSON 协议，所以共用 `rapid.rs` 的进程管理，
  只是启动参数不同）。从 GitHub 发行版下 93MB 的 7z，**核对大小和 SHA-256** 后用 `sevenz-rust2` 解压（包里用了 BCJ2 滤镜，老的 `sevenz-rust` 解不了）
  到数据目录 `engines/paddle`，先解到 `paddle.tmp` 全部成功再改名。要求 AVX。选了 PaddleOCR 但它失败时退回 RapidOCR，再退回系统识字。
  换版本要同时改 `paddle.rs` 里的地址、大小和哈希。
- **识别后自动复制在 Rust 这边做**（`ocr::auto_copy`，`ocr.autoCopy` 默认开）：识字窗口第一次打开时页面可能还没加载完，结果就已经出来了，页面里判断"刚识别完"不可靠。
  复制的格式和窗口里"复制全部"一样（按"保留原始换行"设置）。

### 剪贴板

- **"自己造成的剪贴板变化"按序列号区间忽略，而且能同时存在多段**（`clipboard/mod.rs` `IgnoreState`）。划词翻译是"模拟复制 → 恢复备份"连着做两次，只记一段的话，第一次的变化会在入库线程晚到时被当成新记录。
- **入库线程判定前要等进行中的区间结束**（`should_ignore` 最多等 1 秒）。
- **文本去重前统一换行符**。微信输入法会把刚复制的文字改成 `\n` 换行再写一遍，不统一就出现两条一样的记录。
- **模拟 Ctrl+C / Ctrl+V 之前先松开所有修饰键**（`platform/windows/input.rs` `release_modifiers`）。用户按 Alt+V / Ctrl+Alt+T 时手还没松，直接发会变成 Ctrl+Alt+V。
- **剪贴板面板、翻译气泡、toast 都在启动时预建隐藏**，热键只摆位 + show。
- **剪贴板面板显示期间允许被截图，藏起来时再排除**（`clipboard/panel.rs` `show` / `hide`）。用户就是想截它（Shift+F1 瞬间截屏、F1 都行，截完它会因为失焦收起，但冻结的画面里有）；
  隐藏的窗口不排除会被 WGC 画成白块，所以藏起来时要恢复排除。
- **毛玻璃面板不用 Tauri 的 `set_effects(Acrylic)`，自己挂合成背板**（`wm::set_glass` → `platform::set_backdrop`，`windows/effects.rs`）：
  Win11 上 Acrylic 走 DWM 系统背板，永远铺满整个矩形窗口，`SetWindowRgn` 裁不掉——面板是圆角的，圆角外面露出一块方的毛玻璃，看着像一圈方框阴影（用户报过）；
  系统圆角又只有 8px 一档。现在用 Windows.UI.Composition 在窗口最底下挂一层视觉对象：画刷是系统的宿主背板（`CreateHostBackdropBrush`，
  要先给窗口开 `DWMWA_USE_HOSTBACKDROPBRUSH`），裁剪用圆角矩形几何，半径随便设、边缘抗锯齿。窗口变大小只更新裁剪的尺寸（`wm::track_glass`）。
  合成器要求 UI 线程有 DispatcherQueue，两个都存在线程局部变量里。**Win10 没有这个窗口属性**，挂不上就退回系统亚克力 + 窗口裁剪（旧做法）。
  划词面板和剪贴板面板共用。验证：内置的 `--translate=` 参数弹出面板，F1 冻结画面（WGC，和用户看到的一致）截图看四个角。
- **划词面板不开毛玻璃时，窗口四周的透明边要装得下整个 CSS 阴影**（`SHADOW_PAD` 16，阴影 `0 4px 12px` 正好 16）。以前是 10px 配 `0 8px 28px`，
  阴影在窗口边上被齐齐切断。
- **剪贴板面板毛玻璃时窗口就是面板**：页面里那圈留给阴影的透明边要从窗口尺寸里扣掉（悬浮样式窗口本身四周缩进 8），否则透明边也会铺上亚克力；也没法在窗口里做滑入动画。
- **卡片缩略图按短边生成**（`imaging::card_thumbnail`，短边 ≥ 400、长边 ≤ 1600）：卡片是铺满裁切显示的，按长边缩的话宽截图只剩几十像素高，放大后糊（用户报过）。
  旧缩略图由后台维护一次性重新生成成新文件名（界面按地址缓存图片，同名覆盖看不到变化），旧文件由孤儿清理删掉。
- **来源应用图标按 96px 提取**（`platform/windows/app_icon.rs` `ICON_SIZE`，缓存文件名带 `-96`）：卡片标题栏里的图标 58px，
  4K@150% 上有 87 物理像素，按 48 提取会糊。旧记录由后台维护按 `source_app_path` 一次性重新提取（`maintenance::upgrade_app_icons`），exe 不在了的保留旧图标。
- **卡片编号只在按住 Ctrl 时显示**（`PanelView.tsx` `showKeys`）：按住 160ms 才亮，免得 Ctrl+P / Ctrl+D 这种一按就松的快捷键让编号闪一下；窗口失焦时复位。
- **底部卡片条不用系统滚动条**（`HScrollbar.tsx`）。WebView2 里给元素设了标准的 `scrollbar-width` 之后，`::-webkit-scrollbar` 样式会失效，
  出来的是 Windows 原生的粗灰条带箭头。现在原生滚动条整个隐藏，自己画一根悬浮细胶囊；滚轮竖滚变横滚带缓动（原生 `wheel` 监听，要 `passive: false` 才能拦默认行为）。
- **右键菜单关掉后自己盯着焦点**（`PanelView.tsx` `watchFocus`）：原生右键菜单弹出时面板会失焦（那次按"菜单开着"忽略），
  菜单关掉以后系统不一定再发一次失焦事件，于是点别的软件面板也不收（用户报过）。菜单关掉后每 250ms 问一次 Rust
  "面板还是不是前台窗口"（`window_is_foreground`），不是了就收起。
- **GIF 文件按图片显示**（`ClipCard.tsx` `isGifItem`）：复制单个 .gif 文件时在数据目录留一份副本当预览（`clipboard::gif_copy`，记在 `thumb_path`），
  原文件多半在资源协议读不到的地方；早先的记录在卡片显示时补一份（`clipboard_gif_preview`）。平时显示画在 canvas 上的第一帧，鼠标放上去才挂上 `<img>` 播放，移开就卸掉。
- **单击粘贴 / 双击粘贴**（`clipboard.singleClickPaste`，面板右上角切换）：单击模式下按下照样先选中，松开（`click`）才粘贴，免得拖文字卡片时误粘贴。
- **翻译气泡加载完主动拉取当前文字**（`translate/selection.rs` `CURRENT`）。只靠事件的话，页面还没加载完时事件就丢了，气泡是空的。
- **划词取字后的"回声"处理**（`clipboard::expect_echo`）。微信输入法会在我们恢复剪贴板之后，把刚复制的文字再写一遍，既多出一条历史，又把原内容顶掉。1.5 秒内出现同一段文字就不记录，并再恢复一次原内容。
- **松开 Alt 之前先按一下 0xE8 这个空键**（`input.rs` `MENU_MASK_KEY`）。单独按下又松开 Alt 会激活传统程序的菜单栏；"按住 Alt 选字直接翻译"时我们要替用户松开 Alt。

### 检查更新

- **签名私钥只在发版的电脑上**（`~/.tauri/dato-cor-updater.key`，没有密码），公钥写死在 `update.rs` 的 `PUBKEY`。换钥匙 = 已安装的用户全部验不过新版，只能手动下载一次。
- **防降级**：清单本身没签名，只签了安装包。有人能改清单的话，可以把旧版的安装包（签名是真的）配上一个新版本号骗用户"升级"回旧版。签名的可信注释里带着签名时的文件名，`release.mjs` 把文件名定成 `DATO-OCR_<版本>_x64-setup.exe`，客户端校验文件名里的版本号和清单一致。
- **两个渠道互为兜底**：选国内先试 Gitee 再试 GitHub，反过来也一样。清单放在仓库的 `update/` 下，用两家的 raw 地址取。
- **"不显示更新提示"只跳过这一个版本**（`update.skippedVersion`）；想彻底不看就关"自动检查更新"。手动检查、设置里的"查看"按钮照样能看到被跳过的版本。
- **自动检查发现新版本时右下角提示一次**（每个版本一次，kv `update.notified`）：主窗口平时关着，只在设置页提示的话用户可能一直看不到。
- **安装**：安装包写到 `%TEMP%\DATO-COR-update\`，带 `/P /UPDATE /R` 运行（只显示进度、走更新流程、装完重新打开），程序马上退出让安装包替换文件。

### 划词面板的抽屉动画

- **抽屉从输入框的位置往上长，翻译区跟着往上走，最后对话区盖住翻译区下面一半**（`TranslatePopup.tsx` `openAi`）。
- **窗口挪动和网页重画对不上同一帧**：网页改了之后要过一两帧才上屏，改窗口几乎立刻生效。实测不管先后、等几帧，开头总有一帧面板跳开 130 多像素。
  所以面板弹出时（窗口还没显示）就把窗口往上多留出抽屉要长的那么高（Rust `selection::reserve_above`）：留出来的部分用窗口区域裁掉
  （`platform::set_rect_region`，不显示、点击穿透），毛玻璃背板也只铺在面板上。展开时面板在窗口里往上长，窗口不动。
  上面空间不够时少留或不留，展开时退回挪窗口的老办法。
- **毛玻璃背板跟着面板外框走**（`platform::set_backdrop_rect`）：不然背板先铺满新窗口，面板还没长到那里就露出一块空的毛玻璃。
  展开 / 收起时用系统合成器的动画（`CreateVector2KeyFrameAnimation`，和页面同一条 cubic-bezier），不经过页面每帧通知。
  背板处在"页面指定范围"的状态时，窗口变大小不会自动铺满（`Backdrop.manual`）。
- **展开时宽度不能变**：以前抽屉展开强制最小宽 380，用户的面板是 374，宽度一变就进不了"原地往上长"的分支，走了挪窗口的老办法，
  老办法又没算顶上预留的那截：窗口区域还是旧的、背板恢复铺满窗口，结果右边被裁掉一条、四个角变成方的（用户报过）。
  现在抽屉不改宽度；老办法也按"窗口比面板高出 top"算位置、窗口区域和背板。
- 验证方法：GDI 连拍（`CopyFromScreen`，12ms 一帧）——GDI 截不到毛玻璃，背板正好显示成一块灰，能看出背板范围和面板对不对得上。

### 多端同步

- **收到的记录走 `clipboard::store_remote`，和本机复制同一套分类、哈希、存图**。这样之后在本机再复制同样内容会去重到同一条上，不会出两条。
- **写剪贴板用 `write_own(payload, Some(id))`**：入库线程把这次变化认作"自己写的"，只冒泡不新增、不再发出去。万一没认出来（被别的程序抢先读写），按内容去重命中后会走"又复制了一遍"的路发出去，但 `(sync_id, 发出时间)` 处理过的各设备都会丢掉，最多来回一次；另外刚收到 15 秒内的记录不再发（`ECHO_GUARD`）。
- **转发规则**（`sync::dispatch`）：从哪来的不回哪去。主机收到成员的 → 推给其他成员 + 传网盘；网盘来的 → 推给成员；成员收到主机的 → 只传网盘。
- **网盘上的文件名以发出时间开头**，但不能只按时间游标判断新旧：各设备时钟有偏差，慢的那台发的文件名会排在游标前面被漏掉。所以记的是"处理过的文件名集合"（只留还在网盘上的），存在 kv `sync.webdav.seen`。
- **新设备第一次连网盘只导入最近一天里的最后 10 条，且不写剪贴板**；之后每轮只有最新那条、而且发出时间在 5 分钟内的才写剪贴板，免得开机时把一堆旧内容依次写进剪贴板。
- **手机网页是 http**：浏览器在非安全上下文里没有 WebCrypto、没有 `navigator.clipboard`，所以网页这条路不做应用层加密（靠 Wi-Fi 加密 + 只接受局域网地址），复制用 `execCommand('copy')`，长文字要提前取好（异步取完再复制会丢掉"用户手势"，iOS 不让复制）。
- **网页登录态用 HttpOnly Cookie**（`EventSource` 不能带自定义头），快捷指令用 `Authorization: Bearer` 头。库里只存令牌的 SHA-256。
- **电脑之间的认证头是用专属密钥加密的当前时间**（5 分钟内有效）。重放只能多开一条 SSE，推下来的内容对方解不开；推上来的记录重放会按 `sync_id` 去重。
- **主机停服务前先断开所有 SSE**（`Host::disconnect_all`），否则 axum 的优雅关闭会一直等长连接。
- **macOS**：同步模块本身是跨平台的，但 `platform::protect`（存密钥）和剪贴板监听在 Mac 上还是桩，Mac 端要先把这两块补上（Keychain、`NSPasteboard.changeCount` 轮询）。

### AI 对话

- **密钥按服务商存数据库（`ai_key:{服务商id}`，DPAPI 加密）**，settings.json 里只有服务商的名称、地址、模型列表。
- **回答走 Tauri `Channel` 流式推送**，每次请求有前端生成的 id，`ai_cancel` 按 id 中止后台任务。
- **SSE 按字节攒到整行再解码**（`ai::Sse`）。网络包可能把一个汉字拆成两半，按块解码会出乱码；模拟服务故意这样拆着发来验证。
- **AI 用自己的 HTTP 客户端**（`net::Purpose::Ai`：不设总超时，读超时 120 秒）。翻译那个 5 秒总超时会把长回答掐断。
- **截图带进对话时先缩到长边 2000 像素**，再编 PNG。4K 截图原样发送又慢又费额度。
- **划词面板展开 AI 后点别处不收起**，否则对话就没了；挪到独立窗口时把已有对话原样带过去（`AiContext.history`）。
- **思考深度（auto / low / medium / high / max）每次准备好几份请求体，服务回 400 / 422 就换下一份更保守的**（`ai::send_first_ok`）。
  各家参数不统一，不这样做的话，模型一不认参数用户就只看到报错：
  - OpenAI 兼容：`reasoning_effort`，最高档先发 `xhigh`，不认退 `high`，再不认就去掉参数，并提示"这个模型不支持调节思考深度"
  - Anthropic：新一代 Claude 发 `thinking: {type: "adaptive", display: "summarized"}` + `output_config.effort`；
    4.5 及更早（`legacy_claude` 按模型名认）发 `budget_tokens`，`max_tokens` 必须比它大
  - 最后一份只留必填项（不带温度、思考参数），`max_tokens` 用 8192
- **新一代 Claude（Opus 4.7 起、Sonnet 5、Fable……）和 OpenAI 推理模型不收温度**，发了直接 400；按模型名认出来就不发（`fixed_sampling`），认漏了靠上面的重试兜底。
- **思考过程单独推给前端**（`ChatEvent::Reasoning`）：Claude 的 `thinking_delta`、DeepSeek / 通义的 `reasoning_content`、OpenRouter / Ollama 的 `reasoning`。还在想时展开，开始回答后自动收起。

### 划词翻译面板

- **只有拖右下角手柄引起的尺寸变化才写回设置**（`userResizing`）。面板弹出时 Rust 摆位、展开 AI 都会改窗口大小，不区分的话"自动高度"会被悄悄改成固定值。
- **拖手柄、拖着挪位置期间不响应失焦**（`userResizing` / `userMoving`）：系统进入调整大小、移动模式时会短暂拿走焦点，按"点外面就收起"的逻辑面板会被收掉。挪完把焦点要回来，之后点外面才能照常收起。
- **失焦后等 200ms 再确认**（`onFocus`）：Tauri 给无边框可改大小的窗口盖了一圈原生的改大小边框（`tauri-runtime-wry` 的 `undecorated_resizing`，
  一个只有边上一圈的子窗口，约 6 物理像素）。按在这圈上页面收不到任何指针事件，进入改大小时焦点会"失→得→失→得"闪一下，
  以前第一次失焦就把面板收了——毛玻璃时面板边就是窗口边，拖下边缘必中（用户报过，真机复现过）。
  现在失焦后等一下，焦点回来了就不收，并且"刚失焦又拿回焦点"当成用户在拖边，改完的尺寸照样记进设置。
- **页面只在用户自己拖边改大小时才设窗口区域和背板**（`onResized` 里的 `userResizing`）。弹出时 Rust 摆位也会触发 resize 事件，页面那时手里的预留高度是上一次弹出的、窗口高度是摆到一半的，设区域的命令又排在 Rust 后面执行，会把正确的区域盖掉：面板下面被裁掉一截，或者顶上多出一块空的毛玻璃（展开过抽屉再关掉后的下一次弹出必现，平时偶现）。
- **抽屉展开 / 收起时，翻译区被抽屉盖住的那一截同步裁掉**（`paneStyle` 的 `clip-path`，和抽屉同一条曲线）。面板不透明度 < 1 时抽屉是半透明的，不裁的话下面的译文和输入框透上来，动画结束又突然消失（用户录的 GIF 里看得到）。
- **面板往外长时毛玻璃背板晚 3 帧开始动**（`lagBackdrop`）：背板是系统合成器的动画，命令一到就动，页面过渡要两三帧才上屏，同时开始会先露出一条空的毛玻璃。
- **多个翻译源那一列的滚动条放在右边留白里，位置一直留着**（`scrollbar-gutter: stable` + 负的右外边距）：以前一出滚动条卡片就被挤窄，左右留白不一样宽。
- **底部输入框背后有一层遮罩**（`.pop-ask-wrap`）：从输入框上沿到面板底边，颜色至少八成实、带模糊。以前是一段从透明开始的渐变，面板调透一点，滚到后面的译文就和输入框里的字叠在一起。
- **能拖着挪面板的地方**：原文那一栏（按住拖是挪，点一下是改原文，`dragBySource`）、语言那一行的所有空白。以前只有语言行里二十几像素的一条缝，用户钉住后找不到地方拖，以为挪不了。
- **置顶按钮**（语言那一行，问 AI 左边）：钉住后点外面不收起，Esc 和关闭按钮照样关；只在这次运行里有效，不记进设置。
- **问 AI 两种布局都装在同一个外框里**（`.pop-shell`）。抽屉：对话卡片从底部滑上来压住翻译区下沿；侧边：翻译卡片压住对话区左沿。
- **每块区域只涂一层底色**：卡片圆角外露出来的那一小块用径向渐变补上下层的颜色，不让两块叠在一起。叠了的话调不透明度时重叠处两层叠加，看起来一块透一块不透（用户报过）。
- **展开 / 收起 AI 的动画：窗口一步到位，动画全在页面里做**（`openAi` / `closeAi`）。
  1. 外框先按原尺寸定住（要往回挪的话同时往反方向偏）并同步提交（`flushSync`）；
  2. `system.setBounds` 一次原生调用同时改位置和大小（`SetWindowPos`，分开调会多出一帧中间状态）；
  3. 外框用 CSS 过渡长到新尺寸。对话区贴着外框底边（侧边是右边），高度从 0 长出来、和外框同一条曲线，
     顶边就从翻译区底部平滑升上来，中间不露缝；里面的内容按最终尺寸固定，不跟着重排。
  - **外框必须 `overflow: clip`，对话框聚焦要 `preventScroll`**：`hidden` 的元素还能被滚动，抽屉里的输入框一聚焦，
    浏览器会把整个外框滚上去露出它，整块内容跳一下（胶片图里看得很清楚）。
  - 窗口位置、屏幕可用区域直接读 `window.screenX/Y`、`screen.avail*`（同步、逻辑像素），少几次 IPC，点下去马上动。
  - 测动画用胶片图：点按钮的同时每隔二三十毫秒截一帧拼起来看（测试时临时写的脚本，没进库）。
- **毛玻璃用系统亚克力**（`translate::selection::apply_popup_material`），实测 Blur 背后是黑的、开系统阴影窗口会变大；亚克力自带色调，页面色调要淡（30%～50%）。毛玻璃时页面不留阴影边、不画圆角（`--pop-pad: 0`），圆角是系统的。

### 划词悬浮按钮

- **按钮窗口加了 `WS_EX_NOACTIVATE`，点击由全局鼠标钩子吞掉**（`platform/windows/selection_hook.rs`）。点击一旦到达任何窗口，被选文字的程序就会失去焦点或选区，Ctrl+C 就取不到字了。
- **显示用原生"显示但不激活"，隐藏也要走原生 `ShowWindow(SW_HIDE)`**（`platform::hide_window`）。只调 Tauri 的 `hide()` 时实测按钮会留在屏上。
- **只在 I 形文本光标下的拖选 / 双击才弹按钮**。不看光标的话，拖窗口、拖文件、框选桌面图标都会弹。

### 其他

- **toast 窗口显示走原生"显示但不激活"，隐藏也必须走原生**（`toast_hide` 里的 `platform::hide_window`）。只调 Tauri 的 `hide()` 会和原生状态对不上，窗口一直挂着（透明、点击穿透，看不出来但一直占着合成）。
- **单实例插件必须第一个注册**（`lib.rs`），否则第二个实例会先把别的插件初始化一遍。
- **启动 3 秒后重试注册失败的热键**。有的程序启动时占着 F1 等键，稍后会释放。
- **设置文件读入时做迁移**（`settings.rs` `sanitized`）：旧版的翻译源 id `microsoft` 映射成 `bing`，未知 id 丢弃。
- **保存设置要排队**：Rust 端 `settings_set` 加锁，前端 `useSettingsStore.update` 一次只发一个、排队期间只发最后那份。拖滑杆、取色时每秒几十次，同时写同一个临时文件会报"系统找不到指定的文件"，颜色也会被回滚（用户报过）。
- **设置页取色不用 `<input type="color">`**（`ui/ColorPicker.tsx`）：WebView2 里那个系统弹窗贴着窗口右边会被裁掉一半。吸管用浏览器的 `EyeDropper`。

### 截图遮罩拖动的性能

低配机上拖选区不跟手（用户和微信截图比过）。改了四处，都在 `CaptureView.tsx` / `engine.ts` / `capture.css`：
- **鼠标移动合并到每帧一次**（`onPointerMove` → `flushMove`）：高回报率鼠标一秒 500–1000 个事件，每个都重算 + 重渲染整个遮罩。画笔 / 手绘马赛克不合并（要每个点）；按下、松开前先把攒着的那次处理掉。
- **压暗不用整屏 clip-path 挖洞**，改成选区四周四块纯色矩形 + 圆角时四个角块（`Mask`）。clip-path 一变就整屏重新光栅化（4K 屏 800 多万像素）；现在每块各自一层、只改位置大小。
  合并 macOS 版之后四块都是固定大小的小图层、用 `scale` 拉到位（WebKit 上图层一变大小就整块重画，见 9.3）。
  **底块是 100×100，不能是 1×1**（`STRETCH_BASE`）：Windows 150% 缩放下 1 个 CSS 像素是 1.5 个物理像素，会被对齐成 2 个，
  一拉伸遮罩和框线都大三分之一、伸到选区外面（0.3.1 出过，macOS 是整数倍缩放所以看不出来）。
- **选区框、悬停框的描边阴影不用 `filter: drop-shadow`**，改成 box-shadow 细边：滤镜要离屏再模糊，框一变大小就整块重做。
  合并 macOS 版之后选区框是 `FrameBox`（四条边 + 四个角的小图层，暗边垫在线下面、只往外多出一圈），效果一样，见 9.3。
- **已提交标注的画布空着时，`setClip` 不再整块清空重画**（4K 画布清一次几毫秒，还要整张重新上传）。

量法（`--disable-gpu` 软件渲染模拟显卡不行的机器，CDP 把主线程降速 4 倍模拟慢 CPU，同一段 3.5 秒的来回拖动，DevTools 跟踪统计）：
光栅化 1936ms → 246ms，事件处理 338ms → 76ms，3.5 秒出帧 209 → 318，帧间隔 p95 30ms → 18ms。
验证遮罩画得对不对用 CDP 的 `Page.captureScreenshot`（GDI 截屏拍不到遮罩那层半透明）。

- **拖柄落在框线正中**：框线是 outline，画在选区外面一圈，拖柄按 `--sx/--sy` 往外挪半个线宽。四个角是圆点，四条边中间是短横条。
- **二级工具条对准它的工具按钮**（`useToolAnchor`，工具按钮带 `data-tool`）。条件渲染的元素量大小要把"在不在"传给 `useElementSize` 的 `deps`，
  否则只在第一次挂载时找元素，找不到就一直用默认宽度——二级条一直对不齐就是这个原因。

### 标注

- **撤销按快照回退**（`AnnotationEngine.checkpoint`）：加、挪、改样式、删、整批加译文都先存一份。只 pop 最后一个标注的话，挪动、改大小撤不回来。
- **文字单击 = 选中（可拖、四角按比例缩放字号），双击 = 改字**。拖动要超过 3 物理像素才算挪，免得手抖。
- **打字时按右键 = 提交文字，不退出截图**（`swallowMenu`）：右键按下时输入框先失焦、文字已提交，紧跟着的
  contextmenu 若照常处理就会把整个截图退掉，刚打的字全没了（用户报过）。
- **矩形马赛克拖动时就画出打码效果**（用户要求），格子颜色按绝对位置缓存（`render.ts` `rectCache`）：往右下拖时起点不变，算过的格子直接用；
  按整格取色，框边上的半格颜色不会随框大小变，拖动时不闪。
- **画笔和涂抹马赛克时点哪都是接着画**，不去选中已有标注（`canPick`），不然在旧笔画上起笔会变成拖动它。
- **截图原位翻译不用识字窗口的段落重组**（`capture/region_translate.rs` `layout_blocks`）：reflow 为了复制成文本会把左右两栏同一水平线的字拼成一行；这里行里隔得远的拆开，再按上下挨着、左对齐、字号相近、**字色相近**拼块。所有块用空行连成一次请求（免费源 3 秒限流），拆不回来再逐块补翻。
- **长图先开编辑窗口，再编码入库**（`longshot::finish` + `editor::attach_screenshot`）。反过来的话，调试版要白屏好几秒。

## 4. 踩过的坑（环境和测试相关）

- **有的前台程序会吞掉全局热键**（实测远程控制软件 GameViewer 在前台时 F1 无反应）。不是 DATO OCR 的 bug，测热键前先把焦点切到普通窗口。
- **远程控制软件会改写剪贴板**：图片被转成 `FileGroupDescriptorW` 虚拟文件，文字被统一成 `\n`。在开着远程软件的机器上测剪贴板，要分清是谁写的（`GetClipboardOwner`）。
- **合成的滚轮事件到不了 WebView2**（`mouse_event` / `SendInput` 都不行），真人滚轮没问题。自动化测长截图要用 WinForms 之类的原生窗口当目标（`scripts/test/scrollwin.ps1`）。
- **测试脚本自己必须声明 Per-Monitor-V2 DPI 感知**，否则坐标全被虚拟化（4K@150% 会被报成 2560×1440）。
- **含中文的 .ps1 要存带 BOM 的 UTF-8**，否则 Windows PowerShell 5.1 按 ANSI 读，报出毫不相干的语法错。
- **Git Bash 里的 `tar` 是 GNU tar**，解不了 7z，还会把 `C:` 当成远程主机。`fetch-ocr.mjs` 显式用 `System32\tar.exe`。
- **开发模式下前端热更新可能和整页重载撞车**，日志里出现 `insertBefore` / `removeChild` 的 React 报错，重启 `tauri dev` 即可，正式版不会有。
- **测试脚本的点击会落到最上面那个窗口**，可能是别人正在用的程序（实测发生过：点进了远程桌面里的别的程序）。`input.ps1` 现在默认只允许点 DATO OCR 和 pwsh 测试窗口，其它一律拦下；要放宽用 `CHENOCR_TEST_ALLOW` / `CHENOCR_TEST_TITLE`。
- **别用新配置目录启动 Edge 做测试**：Edge 会用 Windows 账户自动登录并开始同步浏览数据。懒加载场景用原生的 `scripts/test/lazywin.ps1`。
- **截 DATO OCR 主窗口用 `winshot.ps1`（PrintWindow）**，窗口被挡着也能截；要切页面用 `chenocr.exe --page=settings:translate`，运行中的实例会跳过去，不用点。
- **要看划词面板用 `chenocr.exe "--translate=一段文字"`**：运行中的实例在鼠标旁边弹出面板翻译这段文字，不用选字、不用按热键。
- 单实例插件会建一个 22×22 的辅助窗口 `com.chenocr.app-siw`，状态是"可见"，位于 (0,0)。目前没看到它在屏幕上留下痕迹，如果有人反馈左上角有小方块，先查它。

## 5. 没验证 / 没做的

**需要第二块显示器才能验证**（规格 08 M0 遗留，最重要）：
- 主屏 150% + 副屏 100% 混合 DPI 下，两块屏的底图、遮罩、选区都不错位不模糊
- 副屏在主屏左侧（负坐标）
- 双屏下的热键→可见延迟（抓屏和底图上屏都随屏数线性增长，单屏的 80ms 不能外推）

**需要真人操作才能验证**：
- 在 Chrome、微信、VS Code、Excel，以及真实的 B 站 / YouTube 里长截图（规格 03 §8）。懒加载、悬浮按钮、固定顶栏都有单元测试和模拟窗口验证，但没在这些应用里真跑过
- 划词悬浮按钮在各种程序里的误触发情况（只在 RichTextBox 里测过）；"按住 Alt 选字"没测（Ctrl 测过）
- 自定义代理（http / socks5）
- 微信输入法回写剪贴板的"回声"处理：逻辑已加，但之后的测试里输入法没再回写，没实际触发过

**PaddleOCR 没验证的**：应用里点"下载"完整跑一遍（下载地址、哈希、解压、识别都单独测过：`cargo test paddle_extract_and_run -- --ignored`，

| `lazywin.ps1` | 长截图目标：模拟视频站首页（固定顶栏、懒加载封面、滚到底加载更多、右下角悬浮按钮），卡片带编号 |
| `childwin.ps1` | 列出某个进程窗口下的子窗口（类名、可见性、矩形），排查自动框选框不到某块区域 |
| `lazy-page.html` | 同样场景的网页版。**不要用新配置目录的 Edge 打开**（见第 4 节） |
| `mock-ai.mjs` | 本地模拟 AI 服务（OpenAI 兼容 + Anthropic、流式、故意拆开多字节字符、模拟思考过程和不认参数的 400），请求摘要写到 `mock-ai.log` |

典型流程：用 `CHENOCR_ALLOW_SELF_CAPTURE=1 corepack pnpm tauri dev` 启动（否则截不到 DATO OCR 自己的窗口）→
`input.ps1` 发热键和鼠标 → `shot.ps1` 截图看界面 → 读 `%APPDATA%\DATO OCR\logs\` 里的日志确认时序和结果。

**这些脚本会真的动你的鼠标键盘和剪贴板**。别人正在用的机器上跑之前先打招呼；
每次动作前确认目标窗口还在（测试窗口有自动关闭计时），否则拖拽、按键会落到别的程序上。
测试窗口启动要几秒（PowerShell 要先编译内嵌的 C#），**等它出现并画完再按热键**，否则截到的是它出现之前的桌面 —— 这曾被误判成"抓屏拿到旧帧"。

### 9.2 和 Windows 不一样的地方

| # | Windows | macOS | 原因 |
|---|---|---|---|
| 1 | 浮层是置顶窗口 | **不激活应用的 NSPanel**（`effects::build_floating`：给 tao 的窗口类补一个 `+alloc`，建浮层的那一次分配成面板） | 普通窗口要收键盘就得激活整个应用：用户正在用的程序被切走、别的应用全屏时窗口出不来、事后还得还焦点。面板没有这些问题 |
| 2 | 物理像素的虚拟桌面是系统给的 | 系统只有"点"，`geometry` 负责换算：屏的物理原点 = 点原点 × 所有屏里最大的缩放，尺寸 = 点 × 本屏缩放 | 直接按"点 × 本屏缩放"算，缩放不同的两块屏的物理矩形会重叠 |
| 3 | xcap + WGC | `CGWindowListCreateImage`，再画进 sRGB 位图 | 实测比 `CGDisplayCreateImage` 快；屏幕是 Display P3，不转的话取色器读数和存出去的图都偏色（纯品红读出来是 #EA33F7） |
| 4 | RapidOCR + 系统 OCR 兜底 | 只有系统的 Vision | RapidOCR-json 没有 macOS 版；Vision 中英文都准、零体积。`ocr::recognize` 里找不到 RapidOCR 就直接用系统的 |
| 5 | F1 / F2 / F3 / Shift+F1 | ⌥1 / ⌥2 / ⌥3 / ⌥⇧1（`platform::default_hotkeys`） | 笔记本的 F1–F3 默认是亮度和调度中心。项目所有者选的 |
| 6 | DPAPI | 钥匙串里放一把随机主密钥，密钥表的内容用它做 AES-256-GCM | 接口是"明文 → 密文"，密文照旧存数据库 |
| 7 | 长截图把焦点交给被滚动的窗口，按键靠全局键盘钩子 | 遮罩一直握着键盘焦点，按键由本地监听收；有「辅助功能」权限时再加一个 CGEventTap 全局兜底 | macOS 的滚轮跟着鼠标走，和焦点无关；不依赖权限也能用 |
| 8 | 划词监听是 WH_MOUSE_LL | `NSEvent` 的全局 + 本地监听 | 只读鼠标事件不需要权限。取字（模拟 ⌘C）仍然要「辅助功能」 |
| 9 | 截图时能框到窗口里的控件 | 只能框整个窗口 | 控件矩形要走辅助功能接口逐个跨进程去问，一个浏览器窗口几千次往返，赶不上热键到遮罩出现的预算 |
| 10 | 剪贴板有变化通知；图片写 DIB | 200ms 轮询 `changeCount`；图片写 TIFF（不压缩，等于一次内存拷贝） | 系统没有通知机制 |
| 11 | 页面自己画标题栏按钮 | 系统的红黄绿灯叠在页面上（`titleBarStyle: Overlay`），页面不画按钮、给它让出位置 | 主窗口的在 `tauri.macos.conf.json`，其余窗口走 `wm::framed_builder` |
| 12 | 托盘左键开主窗口、右键弹菜单 | 菜单栏图标用单色模板图，左键就弹菜单；点程序坞图标叫回主窗口 | 平台习惯 |
| 13 | — | 设置页多一组"系统权限"（屏幕录制、辅助功能）的状态和"去授权"按钮 | macOS 特有 |
| 14 | GIF 录屏用 WGC 推流，画面变了才来一帧（整块屏，再裁出选区） | 按拍子只抓选区那一块（`capture::ScreenRecorder`），画面没变也返回一帧 | 实现简单；相同的帧编码时不占体积。只抓选区是因为抓整屏太慢：正式版实测 3420×2224 整屏一帧 64ms（5K 屏还要翻倍），1201×721 的选区一帧 21ms。所以录屏接口改成了 `start(显示器, 区域)`、`next` 直接给裁好的画面 |
| 15 | 毛玻璃背板是 DWM 的合成视觉对象，圆角靠几何裁剪 | 垫在网页下面的一块 `NSVisualEffectView`（`effects::set_backdrop`），圆角是图层圆角，范围动画用 `NSAnimationContext` + 同一条贝塞尔曲线 | Tauri 的 `set_effects` 建的视图永远铺满窗口，没法只铺一块、也没法做动画 |
| 16 | 窗口区域（`SetWindowRgn`）：区域外不显示、点击穿透 | 窗口本来就透明，只补"点击穿透"：定时（30Hz）看鼠标，在窗口里但不在保留的那块上就 `ignoresMouseEvents` | macOS 没有窗口区域 |
| 17 | "是不是前台窗口"比窗口句柄 | 看是不是焦点窗口（`isKeyWindow`） | 浮层拿键盘焦点时应用并不在前台，系统的前台窗口还是别的程序的 |

界面文案里 macOS 和 Windows 不一样的（系统叫法、默认热键、按键名）在 `src/i18n/mac.ts`，启动时叠到基础文案上。
应用内快捷键代码里统一写 `Ctrl+Z`，按键处理 Ctrl 和 ⌘ 都认（`modKey`），显示时 macOS 换成 `⌘Z`（`shortcutLabel`）。

### 9.3 不能删的东西（macOS）

- **浮层一律用 `platform::build_floating` 建，面板是"出生时"就定的，不要改成建好之后再换类**（`object_setClass`，
  tauri-nspanel 插件的做法）。第一版就是那么做的：WKWebView 和 AppKit 都会对窗口挂属性监听（KVO），监听按对象当时的
  类登记，类一换，之后注销监听就抛 `NSRangeException`，在 Rust 里表现为 `Rust cannot catch foreign exceptions` 直接
  退出。**凡是销毁浮层窗口都会触发**：拔掉显示器后第一次截图、关掉任何一张贴图。把内容视图先摘下来也没用，
  AppKit 自己还挂着一个 `_windowLayerContext` 的监听。
- **面板类要有名叫 `focusable` 的成员变量**（`effects::panel_class`）：tao 建完窗口会按名字去写它，没有就 panic。
- **遮罩、选区框、尺寸提示、放大镜的画法别改回"一整块"**（`CaptureView.tsx` 的 `Mask` / `FrameBox`，写法和量出来的
  数字都在注释里）。WebKit 上元素有多大、重画就有多贵：原来选区框是一个和选区一样大的带 outline 的元素，
  拖到全屏时光是它每帧就要 3–4ms；现在全是只靠 transform 挪的小图层。带模糊阴影、玻璃材质的东西不要放在每帧都变的元素上。
- **`AnnotationEngine.renderCommitted` 在没有标注时直接返回**。拖选区每动一下都会调到它，画布和屏幕一样大，
  哪怕只清空一遍也要把整块画布重新提交给合成器。
- **窗口摆位一律走 `platform::place_window` / `set_bounds_logical`**。tao 的 `set_position` / `set_size` 在 macOS 上是
  排到下一轮事件循环才执行的，紧跟着 `show()` 窗口会先在旧位置闪一下；而且它按窗口**当前所在屏**的缩放换算，
  跨到缩放不同的屏时位置是错的。
- **浮层拿焦点走 `platform::take_focus`，不要直接 `set_focus()`**：后者会 `activateIgnoringOtherApps`，面板就白做了。
- **AppKit 的调用全部经 `util::on_main`**。上层的 command 多半跑在工作线程上，在那里碰 NSWindow 是未定义行为。
- **`NSScreen` 只在主线程读，结果缓存给别的线程用**（`geometry::extras`）。显示器的几何用 CoreGraphics 现查，任何线程都行。
- **抓屏不逐像素补 alpha**（`util::rgba_from_cgimage` 的 `opaque` 路径）：4K 屏在调试版里要一百多毫秒，
  和 Windows 一样留给 `imaging::crop_opaque`。
- **`NSEvent` 监听句柄要整个结构体一起带进主线程的闭包**（`hook::Monitors::remove`）：Rust 2021 的闭包按字段捕获，
  只写 `self.0` 的话带进去的是里面那个不能跨线程的句柄，编译不过。
- **没有屏幕录制权限时启动不预热抓屏**（`capture::warm_up`），否则一打开应用就弹授权框。
- **静默启动后把前台还给原来的应用**（`after_silent_start`）：macOS 会把新启动的应用切到前台，哪怕它一个窗口都没有。
- **`build.rs` 构建前清 `._` 文件、ESLint 忽略 `**/._*`**：见 9.4 第一条。
- **`place_window` 排在下一轮的"再摆一次"摆的是最新要的位置**（`effects::PENDING_FRAME`）。划词面板弹出时先 `place_window`、
  紧接着 `set_bounds` 往上多留一截；要是下一轮还按第一次的位置摆，预留区就没了，面板里的内容整个往下错一截。
- **划词面板的预留区按 `wm::rect_on_monitor` 的结果算，不要改回 `window.outer_position()`**：Tauri 报的物理坐标是
  "点 × 本屏缩放"，和这一层的坐标（9.2 第 2 条）在缩放不同的副屏上不是一套。
- **盯鼠标的定时器在带区域的窗口都藏起来两秒后停表**（`effects::region_tick`），下次设区域再开 —— 划词面板每次弹出都会
  重新设一遍。不停的话面板藏着的时候也一直每秒醒 30 次。
- **遮罩的压暗块、选区框的实线边是固定大小（100×100）的图层用 `scale` 拉到位**，不要改成直接给宽高（0.3.0 上游的写法，Chromium 没问题）：
  WebKit 里图层一变大小就整块重新光栅化。选区框的暗边只往外多出一圈（上游的结论：选区贴着屏幕边时里边那圈会变成一条黑线）。
- **尺寸提示不加 `backdrop-filter`**：遮罩窗口是透明的，截图在底下另一个窗口里，本来也模糊不到，白白每帧重算。

### 9.4 踩过的坑（macOS 环境）

- **项目放在 exFAT 的移动硬盘上会出三种怪事**：
  1. macOS 给每个带扩展属性的文件生成一个 `._名字` 伴生文件（从非系统程序里启动的进程写的文件都带）。
     Tauri 的构建脚本把 `capabilities/`、它自己输出目录里的每个文件都当配置解析，读到它们报
     `stream did not contain valid UTF-8`；ESLint 会去解析 `._eslint.config.mjs`。
  2. 这块盘的簇大小是 1MB，每个小文件占 1MB：一次没编完的 `cargo check` 就写了 8.7GB。
  3. 不支持硬链接。
  
  所以**编译产物不能放在这块盘上**：这台机器在盘上建了一个 APFS 磁盘映像（`/Volumes/Extreme SSD/DatoCorBuild.sparseimage`，
  挂载在 `/Volumes/DatoCorBuild`），项目根的 `.cargo/config.toml`（本机配置，不入库）把 `target-dir` 指过去。
  重启或重新插盘后要先双击映像挂载，否则 cargo 报建不了目录。
- **权限算在谁头上**：`tauri dev` 跑的是裸可执行文件，屏幕录制 / 辅助功能权限算在启动它的那个程序（终端）头上；
  打包后的 `.app` 才算在 DATO OCR 自己头上。
- **本机签名的包，每重新打一次，之前的系统授权就全部作废**（踩过：用户授权、重启了两次，截图还是"点了没反应"）。
  没有开发者证书时只能做本机签名，它默认拿整个程序的哈希当身份（`codesign -dr -` 显示 `designated => cdhash …`），
  而系统的授权是记在这个身份上的；系统设置里那一项却还显示开着。所以**打包用 `corepack pnpm build:mac`**：
  它在 `tauri build` 之后跑 `scripts/mac-sign.mjs`，把身份固定成只认包标识，以后重新打包授权不丢。
  已经失效的旧授权要清一次：`tccutil reset ScreenCapture com.datocor.app`、`tccutil reset Accessibility com.datocor.app`，再重新授权。
- **缺屏幕录制权限时，截图失败不能只弹提示**（`capture::report_start_failure`）：提示又小又短，而从主窗口点的截图，
  主窗口这时已经藏起来了。现在会把主窗口叫回来、停在设置页的"系统权限"上。
- **钥匙串同理**：重新编译后的程序读主密钥时系统会再问一次，点"始终允许"。
- **剪贴板历史可能要再过一道系统确认**：新版 macOS 在程序不经用户操作就读剪贴板时会弹框询问
  （系统设置 → 隐私与安全性 →"从其他 App 粘贴"），要选"允许"。这次只验证了读我们自己写进去的内容，
  读别的程序复制的内容时实际怎么弹没见到。
- **`tauri build` 会核对 Rust 的 `tauri` 和前端的 `@tauri-apps/api` 的主次版本**，对不上直接失败（`tauri dev` 只警告）。
  这次把前端包从 2.11.1 升到了 2.12.1。
- **Vision 第一次用要给系统建模型缓存**，实测那一次 8 秒，之后每次 ~300ms。
- **`screencapture -l <窗口号>` 可以只拍某个窗口**，不用拍整屏；窗口号从 `CGWindowListCopyWindowInfo` 查。
- **量遮罩的流畅度不能只看帧间隔**：60Hz 的屏上每帧只要低于 16ms 就看不出差别，而且光栅化在 WebKit 的 GPU 进程里、
  合成在 WindowServer 里，都不在页面主线程上。`scripts/test/mac-overlay-bench.sh` 在遮罩里合成拖动事件，同时量这几个
  进程的 CPU 时间；它的 `css` 选项可以临时隐藏某个元素来逐项排查。WindowServer 那一项会混进别的程序的动静，
  要对比就新旧交替着测。只要画面上有东西在变，WindowServer 每帧固定要 ~3ms，省不掉。
- **排查 Objective-C 异常**：临时给 `objc2` 加 `catch-all` 特性（`objc2 = { version = "0.6", features = ["catch-all"] }`），
  异常会变成带原因和调用栈的 Rust panic；不加的话只有一句 `Rust cannot catch foreign exceptions`。查完去掉，它有运行时开销。
- **旧抓屏接口在 macOS 26 上还在**：`CGWindowListCreateImage` 热态 ~15ms，`sharingType = none` 的窗口确实被排除
  （用一个测试窗口实测过）。SDK 里它已标成废弃，哪天真没了换 ScreenCaptureKit，只动 `capture.rs`。

### 9.5 怎么测（macOS）

没有「辅助功能」权限时模拟不了按键和鼠标，所以加了命令行入口，Windows 上也能用：

```bash
chenocr --action=capture     # 等同按截图热键；还有 instant / longshot / ocr / clipboard / translate / ai
chenocr --action=cancel      # 取消正在进行的截图 / 长截图（自动化时别让遮罩卡在屏幕上）
```

调试版另有两个只为测试留的口子（正式版里没有）：

- `chenocr --eval=capture-1:脚本.js`：在指定窗口的页面里执行一段脚本。模拟不了鼠标时就在页面里合成指针事件，
  `scripts/test/overlay-bench.js` 是现成的例子。遮罩页面是常驻的，脚本往里加的样式、打的补丁要自己清掉，不然会留到下一次。
- 环境变量 `CHENOCR_FAKE_MONITOR=某个文件路径`：这个文件存在期间，假装主屏右边多接了一块 1280×720、1x 的屏
  （`geometry::screens`）。启动前建好文件、启动后删掉，就等于"拔掉一块屏"，下一次截图会走销毁遮罩窗口的路径。
  没有真的显示器变化事件，也抓不到那块屏的画面，只用来测窗口的建和销。

第二次启动只是把参数转给已经在跑的那个实例。配合 `CHENOCR_ALLOW_SELF_CAPTURE=1` 启动（否则遮罩和面板拍不到），
用 `screencapture` 拍下来看，再读 `~/Library/Application Support/DATO OCR/logs/` 里的日志。

```bash
cargo test --manifest-path src-tauri/Cargo.toml                      # 多了坐标换算、位图互转、TIFF、加解密的测试
cargo test --manifest-path src-tauri/Cargo.toml -- --ignored --nocapture smoke_capture_all   # 真机抓屏，要屏幕录制权限
CHENOCR_SMOKE_IMAGE=图.png cargo test --manifest-path src-tauri/Cargo.toml -- --ignored --nocapture smoke_recognize
```

接手 macOS 的第一件事：给应用开「屏幕录制」和「辅助功能」，把 9.1 里打 ❓ 的逐项用真手过一遍。
最可能出问题的地方按可能性排：标注打字时输入法候选窗在不在遮罩上面（遮罩在第 1000 层）、
长截图中途点了别的窗口之后 Enter / Esc 还灵不灵、缩放不同的双屏、别的应用全屏时遮罩出不出得来。
